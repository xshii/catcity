# 后续玩法与美术方向

以下为未实现需求，不代表当前功能、已承诺数值或同时开工清单。每次选一个可验证的小循环，沿用[需求总览](game-design.md)与[架构边界](architecture.md)。

## 近期优先级

1. 实机打磨城市选址、步行和钓鱼触控/体感，确保单屏反馈清楚、连续游玩不误触。
2. 丰富猫咪对共同活动的反应：同一结果有个体差异，下次相遇正确引用事实。
3. 扩展可选择品种和居民，再加入一种新的照顾或经营活动。
4. 规则模式与事实评测稳定后，接入可关闭的真实 AI 表达服务。

## 猫咪品种与个体

品种定义提供轮廓、外观选项、特点倾向及游戏能力；实体保存唯一 ID、实际品种/花色/性格、偏好、状态与经历。花色不是品种，品种特点是游戏设计，不作为现实猫咪性格保证。

邀请流程先展示品种和特点，再明确确认生成。预览不消耗 RNG；确认命令才分配 ID 和抽取个体差异。每个展示为有效的特点必须有可观察行为或明确标为描述信息。同品种猫不共享私有关系和记忆；失败操作不花钱、不消耗 ID/RNG。

流浪、来访、暂住、定居沿用同一只猫的 ID，不能重新生成来抹去经历。成年猫用邀请邻居、帮助安居表达；幼猫另设计领养照顾。不加入复杂家庭匹配和连续危机剧情。

## 内容候选

| 内容                      | 最小玩法与关系作用                                 |
| ------------------------- | -------------------------------------------------- |
| 撸猫、梳毛、逗猫、喂食    | 尊重个体意愿，用一项动作获得明确回应，体现偏好     |
| 猫草种植                  | 播种 → 游戏时间生长 → 收获/赠送，形成共同种植经历  |
| 流浪猫收容中心 / 猫咪之家 | 相遇 → 照顾或暂住 → 自愿安居，保留完整个体历史     |
| 猫咪医院                  | 简化照护、休息、探望，不先做复杂诊疗或强制危机     |
| 猫咖、旅馆、公园、家具    | 提供经营目标和具体相处地点，让居民实际使用         |
| 摄影、节日、寻找猫咪      | 收集真实动作与场景，留下可查看的经历               |
| 鱼料理委托 / 简单制作     | 消耗鱼获 → 经营资源与居民回应 → 少量配方/钓具成长  |
| 种植园与猫屎咖啡          | 延后设计种植、加工、供货循环；当前不实现制作或售卖 |

钓鱼后续可考虑少量差异明确的钓具、游戏时间/天气鱼、稀有遭遇和同行事件。避免许可证、装备损坏、死亡掉落、现实签到等待及大量微小数值。每个新小游戏先有一个主要操作、明确结算和连续重开的方式，不预建通用 DSL。

## 教程与美术

教程只引导认识伙伴、建设空间、共同活动、使用所得资源和回顾记忆；提示可回看，已完成的有效行为计入目标。完成后自由经营，不扩成长篇主线。

先统一视角、尺寸、光源、角色轮廓与动作标准，再制作更多品种和建筑。优先表达注视、犹豫、放松、开心与活动参与；短句、耳尾动作和安静共处同样重要。保留减弱动画选项。当前代码绘图可被素材替换，但不改变世界坐标、输入规则和测试观察接口。

新增内容的验收仍包含个体差异、存档、拒绝原子性、种子/命令复现与实际 UI 证据；上线前再做具体经济平衡和美术评审。设计参考见[参考资料](design-references.md)。
