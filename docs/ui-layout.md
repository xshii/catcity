# 界面与输入契约

游戏使用固定单屏：场景铺满整个视口，界面浮在场景上（spec 031），手机与桌面结构相同。主要操作不依赖页面或面板纵向滚动；长内容通过分组/分页显示，不能用裁剪隐藏功能。界面配色见下文「视觉基调」；代码绘图服务辨认角色和反馈，不改变世界状态。

## 场景与导航

| 场景 | 导航与主操作                                                          |
| ---- | --------------------------------------------------------------------- |
| 小城 | 指引 / 猫咪 / 出游；地图铺满，点地、建筑、猫或水域后浮出操作卡        |
| 钓点 | 钓具 / 鱼篓 / 图鉴 / 猫咪；水面铺满，鱼竿键、绿区条及结果卡浮在水面上 |

「猫咪」面板两个场景共用，分页「猫咪」（名册、体力、摸摸、邀请新伙伴）、「说说话」、「共同回忆」；没有常驻侧栏。

名册（spec 041 T-12，布局见 ui-design 5.1）：每只猫一行，排成一列，顺序固定为来到小城的先后（世界里猫的顺序），不按心情或亲密重排；最多 10 只伙伴猫，比页面长时随「猫咪」页在面板内纵向滚动，不横向滚动。一行是一个按钮：头像（随心情与休息变）、名字、性别（屏幕上 ♂ / ♀，读屏读"公 / 母"）、世代徽标（"一代目"，R-34 的写法，`--gen-bg` / `--gen-text`）、心情、亲密，以及体力条与"体力 82"；点一下选中这只猫（两个场景的当前伙伴跟着变），河畔进行中的一竿锁定伙伴时整行不可点。选中的那一行右侧多一个"详情 ›"（读屏"<名字> 的详情"），点开后猫的详情在面板内替换名册（名册、摸摸、和谁生小猫、邀请入口都收起），顶部"‹ 名册"返回，打开时焦点在它上面、返回后回到"详情 ›"。详情（ui-design 5.2）：大头像、名字与性别，一行"品种 · 世代 · 性格"，下面三个分区"现在 / 喜好 / 家人"，点标题（或回车）展开或收起（`aria-expanded`），打开时只展开"现在"：现在是心情（开心时带提示）、亲密（爱心、等级名、进度条与"距「信任」还差 8"）、体力（条、"82/100"与在哪：在小城里、在某处岸边或步行中）；喜好是喜欢的鱼、摸摸发现的部位（没发现时"还不知道"）与品种本领；家人现在写"父母：从别处来到小城""孩子：还没有孩子"（T-24 再写出父母与孩子）。行与详情的元素按猫的 id 做一次、之后只改文字，时钟推进不重建（design 10.2）。显示什么由纯函数 `view/cats/screen.ts` 的 `rosterScreen`、`detailScreen` 决定，文案在同一文件的 `CATS_COPY`；打开的详情与分区是 `view/cats/view-state.ts` 的面板状态；DOM 在 `view/cats/roster.ts`、`view/cats/detail.ts`。

改名与起名框（spec 041 R-16、T-25，布局见 ui-design 5.4"起名的交互"）：猫详情里名字右边一个铅笔按钮（44×44，读屏"给 <名字> 改名字"），点开起名框：确认框层（遮罩 50、卡片 51，盖住面板和设置齿轮），标题"给 <名字> 改个名字"，输入框预填现在的名字，下面一行提示，六个推荐名（`role="radio"` 的一组，读屏组名"推荐的名字"，和输入框里的字相同的那个是鼠尾草选中样式），"↻ 换一批"，最下面"取消"和"就叫这个"。打开时焦点在框上、不在输入框里，所以不弹键盘；点推荐名只填进输入框、不提交；换一批只换推荐名；✕ 清空输入框，清空后提示"不填的话就叫 <第一个推荐名>"，确认就用它；和城里别的猫重名时提示"城里已经有一只<名字>了"，仍可确认；输入框只留 12 个字符（一个表情算一个）并去掉换行和控制字符，到 12 个时提示"名字最多 12 个字"；输入法组字时不改输入框。确认时去掉首尾空白，名字变了才发 `RENAME_CAT`，提示"以后它就叫 <名字> 了。"；取消、Esc、点遮罩不发命令；关闭后焦点回到铅笔。键盘：Tab 依次经过输入框、六个推荐名、换一批、取消、确认并在框内循环（✕ 不在其中），推荐名之间方向键移动、回车选中。键盘弹出时框跟着 `visualViewport` 留在还看得见的部分的中间，框比它高时框内滚动，按钮一行贴在框底。推荐名由 Core 的 `suggestNames(world, salt, page)` 给出（改名的 `salt` 是这只猫的 id 序号，Mochi 为 0），换一批是画面状态。起名框是独立的画面模块 `view/cats/name-dialog.ts`（纯模型 `name-dialog-screen.ts`，文案 `NAME_COPY`），输入标题、确认按钮文字、初始名字与 `salt`，交回名字或取消，生小猫（T-22）复用它；改名的文案在 `view/cats/screen.ts` 的 `CATS_COPY.rename`。名字一律用 `textContent` 或属性写入，地图上的名字标签跟着改名更新。

名册卡与「说说话」头部显示心情档位（spec 032）：档位只取 Core 的 `moodBand`，界面配表情和文字（😸 开心 / 😺 平静 / 😾 有点闷 / 😿 低落），读屏读 aria-label 的纯文字；开心时多一行"开心：遛鱼圈更大，经验更多"。结果卡（「这次的收获」）只显示本页、本次来河畔时看着结束的那一竿（`screen.ts` 的 `resultShown`，看的是钓鱼画面状态的 `watched`）；存档里上一次的结果不显示，离开河畔、刷新或出现新的提示消息后也不再显示。结果卡浮在水面上部，显示 4 秒后自动关闭（`screen.ts` 的 `CATCH_CARD_MS`），点卡片任何位置立即关闭（R-02，都派发钓鱼画面状态的 `dismissed`，与 `said` 一样清掉 `watched`），这次的收获仍在钓具面板的结果行与鱼篓里；卡片底边内侧一条 3px 杏色倒计时条用 CSS 动画在同一时长里从满到空。面板（钓具、鱼篓、图鉴、猫咪）或设置卡打开、页面隐藏时倒计时连同倒计时条暂停，回来后继续剩余时间（`catchCountdown`，计时器在 `fishing/panel.ts`，卡片因任何原因消失时一并清掉）；减少动态效果时倒计时条不动，卡片照样到时关闭。鱼的体长够到这个鱼种的金星时（`screen.ts` 的 `goldCatch`，每次都算），卡片一闪金光、右上角弹出一颗金星（CSS 动画约 1 秒，金光不盖住倒计时条，卡片尺寸位置不变）；减少动态效果时只显示那颗金星。心情变化不弹窗：一竿结束或送礼让档位变了，结果卡、钓鱼结果与送礼提示末尾带一句（一竿结束如"Mochi 心情好起来了（平静）"，钓鱼到不了开心；送礼如"Mochi 心情好起来了（开心）"）。当天第 3 条之后的礼物，送礼提示改为"Mochi 今天已经吃饱啦，这条先收下，明天再好好谢你。"（`view/common/bond.ts` 的 `giftNotice`，spec 038）。文案集中在 `view/common/mood.ts` 的 `MOOD_COPY`。关系等级（spec 036）同样显示在名册卡（一行爱心与等级名）和「说说话」头部下方（爱心、等级名、到下一级的进度条与"距「信任」还差 8"），由纯函数 `view/common/bond.ts` 的 `bondBadge` 决定；达到新等级时在促成它的聊天提示、送礼提示或钓鱼结果末尾带一句"和 Mochi 更熟了：信任"（`bondNote`，比较命令前后快照），聊天达到新等级时面板内进度下方也显示这一句（提示条 6 秒后淡出，面板里的这一句留着），读档不重播。

撸猫（spec 039，布局见 spec 041 ui-design 5.5）：名册下方的"摸摸 <猫名>"打开全屏画面（盖住浮条、面板与提示消息），从上到下是标题与剩余秒数、满足条、节奏提示、侧卧的猫、反应气泡、底部的部位条。猫身上没有按钮和文字：头顶、下巴、后背、肚子是猫身体上看不见的触摸区域（`view/art/cat-petting.ts` 的 `PET_SPOT_REGIONS`，与画法同一套坐标），摸到的一块泛起柔光（最喜欢 `--sakura`、一般 `--apricot`、不喜欢灰），部位条里对应的格子同步高亮。点按或拖动抚摸；部位条的格子也能点，是键盘（方向键选格子、空格抚摸、Esc 离开）和读屏的操作目标；没发现的格子显示"?"，摸过的标出 ♥ 最喜欢 / ○ 还行 / ✕ 不喜欢，名册下方也记着。呼噜声起来时光晕变亮、身体轻微起伏，提示写"呼噜声起来了，现在摸"；摸到不喜欢的部位或摸得太快时整只猫向后缩 1 秒（留在屏幕内），部位条变淡。提示固定在猫的上方、气泡固定在下方，互不重叠。设置齿轮浮在撸猫画面上，位置与其他页面相同，标题行的“不摸了”与满足条的右端让出它；画面是模态对话框，打开时齿轮也归它（`aria-owns`），Tab 在“不摸了”之后到齿轮，在齿轮上按 Esc 同样离开。一局进行中打开设置，这一局暂停：倒计时与呼噜节奏都停，摸不到猫，关掉设置卡后从停下的地方接着走（用户 2026-09-30 决定；撸猫画面状态的 `settingsOpen`）。局末结果页没有部位条，内容垂直居中：猫的一句话、"心情 +N"与心情档位、"亲密 +N"、今天还有几次摸摸会让关系更近。显示什么由纯函数 `view/petting/screen.ts` 的 `pettingScreen` 决定，状态在 `view/petting/view-state.ts`（spec 015）；颜色只用 token。没有声音；减少动态效果时没有过渡。被拒绝的结算会关闭画面并用提示消息说明。

和谁生小猫（spec 041 T-21，布局见 ui-design 5.4）：名册下方、"摸摸 <猫名>"之后是"<猫名> 和谁生小猫…"，点一下（或回车）展开、再点收起（`aria-expanded`）。展开后其他每只猫一格：名字与 ♂ / ♀（读屏读"公 / 母"），下面逐条写它没满足的条件和怎么办，如"✗ Pepper 现在不够开心（平静）：摸摸它，或者送它喜欢的鱼"，都满足时写"✓ 可以"（`--text-good`，缺的条件用 `--text-accent`）；所选的猫自己的条件（"Mochi 自己："）和全城的条件（"全城："：空床位、伙伴猫上限）各只写一次，没有缺的就不显示。只有它一只猫时写"小城里还没有别的猫。"。条件是 Core 的 `core/family.ts`（按对方、自己、全城三组取），文案与分组由纯函数 `view/cats/breed-screen.ts` 的 `breedScreen` 决定；列表只读，选伴侣与生育在 T-22。文字没变时不重建列表，时钟推进不换元素（design 10.2）。猫咪面板是一列（`shell/layout.css`，与邀请名单同一套）：面板标题、返回键与分页不动，打开的那一页比面板长时（列表展开、小屏或猫多）在面板内纵向滚动，不越过面板下沿、不盖到底部工具条，页面两侧与底部留出焦点描边的位置；邀请名单占满这一页、只滚名单本身，让"‹ 名册"不动。收起时名册页仍在一屏内，主要操作不靠滚动。

邀请新伙伴（spec 041 R-12、R-13，布局见 spec 041 ui-design 5.3）：名册末尾（摸摸之后）是"邀请新伙伴（还能邀请 N 只）"（N 取还没来的初代猫与伙伴猫上限 10 只所剩名额中较小的一个），点开后名单在面板内替换名册，顶部"‹ 名册"返回（读屏名"回到名册"），打开时焦点在它上面、关闭后回到入口。名单开头写"新伙伴需要一张空床。现有空床：N"，下面每只还没来的猫一张卡：头像（平静、醒着）、名字、性别（屏幕上是 ♂ / ♀，读屏读"公 / 母"，不用颜色区分）、品种、性格、"喜欢："与喜欢的鱼、品种能吸引的鱼，右下"邀请 · <价格> 金币"。价格对所有候选相同（Core 的 `nextInvitePrice`，只按已邀请的数量算）。Core 会拒绝时按钮禁用，下方用 `--text-accent` 写原因与办法（金币不足写"金币不足：需要 400，现有 320。"，其余取 `ERROR_MESSAGES`，如"没有空床位：先建一座公寓。"），由 `GameSession.check` 试算，只在名单打开时试算。邀请不需要确认框；成功后提示消息写"<名字> 来到了小城，住进了 N 号公寓。"（公寓按建造先后编号），回到名册，新猫的卡片出现在名册里。名单较长时只在面板内滚动，面板标题、分页和"‹ 名册"不动（spec 041 ui-design P2、3.3；这是"面板不纵向滚动"的例外）。卡片按猫各建一次，之后只更新价格、按钮与原因，时钟推进不重建按钮。显示什么由纯函数 `view/cats/invite-screen.ts` 决定，文案在同一文件的 `INVITE_COPY`；DOM 在 `view/cats/invite.ts`。

猫咪表情（风格板「猫咪表情」）：地图上的猫、河畔陪伴的猫与名册头像都是圆脸、樱花粉腮红、暖棕描线，表情与耳朵随档位变：开心眯眼笑、耳朵立起；平静圆眼、耳朵立起；有点闷一字眼、耳朵半垂；低落垂眼带泪、耳朵垂下。空闲恢复体力（Core 的 `catIdle` 且体力未满）时蜷成一团打瞌睡，代替原来的 zZ 文字，名册卡另有读屏可读的"在休息"；步行或钓鱼中的猫不蜷起。河畔陪玩家钓鱼的猫始终醒着（R-01）：河畔画的同伴，以及河畔显示时选中那只猫的名册头像，两竿之间、收获卡显示时也坐着，不读"在休息"；小城里照旧。姿势由纯函数 `view/art/cat-look.ts` 的 `catPose(world, cat, { atRiver })` 决定，Phaser 猫（`view/art/cat.ts` 的 `CatArt.setPose`，换姿势不重建精灵）与 SVG 头像 `catPortrait` 画同一套形状。外观是五项（spec 041 cat-looks.md 1、T-14）：毛色（黑、灰、橘、奶油、白、棕）、花纹（纯色、虎斑、重点色）、白斑（无、手套、围兜、奶牛、双色）、眼色（蓝、铜、黄绿）、脸型（圆、尖、长）。`view/art/cat-look.ts` 的 `catLook(品种, 外观)` 给出一只猫的颜色和各部件，部件由 `view/art/cat-parts.ts` 分层叠出：品种给轮廓，脸型改头形（尖脸下巴收窄，长脸头顶升高、耳朵随之上移），花纹加毛色的深色（虎斑：额头的 M、背上的条纹、尾巴的环；重点色：盖住眼睛和嘴的脸罩、耳朵、尾巴、爪子），白斑加白色块（手套：爪子；围兜：嘴下的下巴和胸口；奶牛：额头和背上的斑块；双色：脸下半、布偶的腮毛、肚子和爪子），眼色只在睁圆的眼睛里显出（深色瞳孔）。地图上的猫、河畔同伴、名册头像、邀请名单的头像和撸猫画面都画这一套；地图和头像没有身体，手套只在撸猫画面里看得到。五项存在猫身上（存档 23），`lookOf(cat)` 取一只猫的外观；六只初代猫的模板穿的是 T-13 的花色（黑白 = 黑 + 双色；奶油、灰、橘 = 纯色）。浅色毛描暖棕线、眼睛用墨色；深色毛（黑、棕）和各毛色的深色描 `--paper` 线，眼睛和嘴也用 `--paper`（黑 5.9:1、棕 4.5:1）；白色块描暖棕线，双色的白色落在轮廓上的那一段另描暖棕。品种看轮廓：布偶脸颊两侧有蓬松的腮毛、尾巴又粗又蓬；英短脸更圆、耳朵更小更圆、尾巴短；田园猫（T-14 PR 2 才入档，现在只在画法里）脸向下巴收成倒三角、耳朵大而立、尾巴细长；蜷睡时的耳朵和绕着身体的尾巴也按品种画。地图上的步行路线用比花色更深的同色系。待机时缓慢呼吸、偶尔眨眼、摇尾巴，只动猫自己的部件，大小与锚点不变；屏幕外的猫和隐藏场景里的猫暂停，减少动态效果时完全静止。「说说话」头部的小头像仍是旧插画。

捏猫画面（spec 041 cat-looks.md 4、T-14）：`view/cats/cat-maker.ts` 是全屏画面（第 40 层，和撸猫同一层，设置齿轮浮在它上面），上方是撸猫画面那种带身体的大猫，随选择实时重画（手套、围兜、奶牛斑都看得到）；下面每一项一排点选按钮（`role="radio"`，选中的鼠尾草高亮），依次是品种（只在输入允许选品种时出现，每个品种写明钓鱼特长，田园猫是"什么鱼都愿意陪你钓"）、毛色、花纹、白斑、眼色、脸型，一排的按钮平分宽度，不横向滚动，矮屏上各排在画面内纵向滚动；最下面是"🎲 随机""取消"和确认（文字由调用方给）。🎲 用调用方注入的随机源为每一排各抽一次，只改画面上的选择；确认把品种和五项交给调用方，取消或 Esc 交回空，然后画面关闭，都不发命令。键盘：Tab 在各排的选中项和三个按钮之间循环（焦点留在画面内），方向键在一排里换选择。文案和选项名在 `cat-maker-screen.ts` 的 `CAT_MAKER_COPY`。新游戏开局由它选流浪猫（见下一段）；测试构建的调试桥 `showCatMaker(input, randoms)` 也能单独打开它、`getCatMakerOutcome()` 读结果；美容院在 T-15。设置齿轮是它 Tab 循环的第一站（齿轮不在画面的标记里，齿轮上的 Tab 和 Esc 也归画面处理）。预览占住选项和按钮之外的高度（至少 22vh，最多 280px 高），高屏上猫更大、留白匀在猫的上下。

开局捡流浪猫（spec 041 cat-looks.md 2、T-14）：新游戏（没有存档时，以及读档被拒绝后点"清除旧试玩存档"时）先是全屏的一句"路边捡到一只流浪猫"（`view/cats/stray.ts`，第 40 层，下面是蜷着的小猫和"抱起它"），点"抱起它"打开捏猫画面，可以选品种（默认田园猫），确认按钮是"就是它了"；确认后用选中的品种和外观开始新游戏并保存，提示"你把它抱回了小城。它叫 Mochi。"；取消或 Esc 回到那句话，不能跳过。这期间城市时钟不走（`main.ts` 看 `view.starting()`），所以没选之前不会存档，刷新后仍从这句话开始。🎲 在游戏里用 View 自己的 `Math.random`。读档被拒绝时不自动显示它，等玩家显式重置。测试构建默认不显示（见 architecture.md 的调试桥一段），正式构建的检查从预先写好的新游戏存档开始（`harness/adapters/catcity/browser.ts` 的 `savedNewGame`）。文案在 `view/cats/stray-screen.ts` 的 `STRAY_COPY`。

顶部半透明浮条是场景切换、时钟、速度键与金币（不再显示品牌栏）；底部浮动工具条是当前场景的入口；提示消息在每个页面都在同一处：顶部浮条下方那一行（小城的“下一步”、河畔的钓点名称）的正下方，高度随文字（至多两行），6 秒后淡出，居中、最宽到屏幕两侧各留 16px。小城在浮条下 40px，正好在设置齿轮的下沿；河畔的钓点名称比“下一步”矮，在浮条下 32px，与齿轮同高，所以河畔的提示消息左右各让出齿轮那一栏（`--gear-room`：齿轮右边距加齿轮宽再留 8px，通常 60px），仍然居中；因此不盖住水面、鱼竿、鱼影、落点圈、设置齿轮、体感的提示，也不盖住钓点名称（390×844、360×640 以及 Safari 带工具栏的 390×664、375×553 都如此）；面板打开时（外壳带 `panel-open`）提示消息改在面板底边、叠在面板之上，左右各留 16px，不盖住面板的标题、分页与按钮；设置卡不是面板，照旧盖住提示消息并在卡内写明原因；结果卡与提示消息在同一位置，二者不同时显示：结果卡出现时收起当时还挂着的那条提示消息（`fishing/screen.ts` 的 `noticeShown`）；结果卡显示期间新出现的提示消息照常显示，结果卡让位消失（钓鱼画面状态的 `said` 事件清掉 `watched`），这次的收获仍在钓具面板的结果行与鱼篓里；下一竿开始后照常显示；浮动界面都避开 iOS 安全区。时钟旁唯一的速度键点一次在 1× → 2× → 4× → 1× 间循环，只改变浏览器前台每现实秒推进的游戏分钟数（倍率见 `CITY_TIME.speeds`），按设备记在 localStorage（读取时校验），不进世界与存档；进入河畔或打开撸猫画面等小游戏时回到 1× 并禁用（显示"钓鱼 1×"或"撸猫 1×"），离开后保持 1×；撸猫画面盖在地点之上，不是一个地点（`common/place.ts` 的 `minigame()` 标志：地点是河畔，或撸猫画面开着）。钓鱼 tick 不受影响。没有其他快进入口；地图卡的"等 10 分钟"只在所选猫步行时出现。

浮条下方常驻一行"下一步"引导，随教程进度变化；完整教程、手动"保存进度"放"指引"页，不显示种子等开发信息。"猫咪"页有名册、摸摸与"邀请新伙伴"；空闲恢复中的猫蜷成一团打瞌睡（读屏读"在休息"），没有休息按钮。"出游"页列出全部水域及解锁条件，点选后在地图定位该水域并安排真实行走，不能直接传送到可钓场景。切换场景关闭面板，单纯开城市面板或刷新快照不切到钓点。

操作卡不提供 Core 会以可知原因拒绝的操作：按钮禁用，卡片下方一行写明原因（由 `GameSession.check` 按 Core 规则试算，文字来自共享的 `ERROR_MESSAGES`）。选猫后点地块打开该地块卡片，在常规操作旁提供"让 <猫名> 走到这里"；点建筑时只显示建筑操作，公寓卡为每只猫列出"入住"。卡片与名册不使用坐标编号，地图也不画行列标签。

步行（spec 014 §6）：步行按钮写明耗时，如"让 Mochi 走到这里 · 约 18 分钟"，Core 会拒绝时不写；选中猫的卡片写一次"草地 6 分钟/格 · 土路 3 · 石路 2"。地图上步行的猫在整步时间里从一格滑到下一格，所以一直在动，2×、4× 与道路上看得出更快。位置由纯函数 `view/city/walk-glide.ts` 算出：`walkGlide`（一步之内的位置与剩余现实毫秒）、`walkerAt`（沿 Core 排定的路线，不超过体力够走的格数）、`leadMinutes`（两次时钟推进之间按真实时间推算，至多领先一次推进；换速从当前位置继续）与 `catchUp`（世界跳变后约一秒内滑到位，不瞬移）。场景每帧应用，名字与选中框跟着猫，镜头照常跟随。体力耗尽暂停的猫站在格上；受阻或重新寻路后回到 Core 所说的格。减少动态效果时不滑行，逐格移动。

长按提起（spec 035）：选中猫时的提示消息末尾带一句“也可以长按猫咪，拖到想去的地方”（`city/screen.ts` 的 `selectedNotice`）。按住猫约 0.35 秒且手指没有移出 8px，猫被提起——影子升到手指上方跟着走，原地的猫变淡，手指下的地块描绿边（能去）或灰边（不能去）。松手即出发，命令与提示和操作卡的"让 <猫名> 走到这里"/"让 <猫名> 走到岸边"相同；不能去的地块、猫自己的格、地图外、松在浮条或卡片上、触摸被取消都不发生任何事。提起期间地图不平移，拖到屏幕边缘不自动滚动；猫不瞬移，沿路线走过去。手势由纯函数 `view/city/cat-drag.ts` 的 `reduceMapGesture` 判定，能不能去由 `catDrop` 向同一张操作卡的按钮取结果，场景只画。没有震动；减少动态效果时影子不做升起动画。画布关闭了 iOS 长按菜单与文字选择。

到岸后的“进入钓点”先进入预瞄，不创建一竿或消耗资源。玩家可点击水面、调滑杆或启用体感确定两轴落点；只有点击“准备抛竿”才执行 `FISH_BEGIN`、扣除体力/鱼饵并锁定落点。已有一竿时返回钓点恢复同一局，不重复创建或扣费。

面板是覆盖层：手机从浮条下铺到工具条上，桌面为右侧 400px 抽屉；点暗处、返回键或 Esc 关闭。地图默认跟随所选猫，可切总览；点同猫取消选择，选中框消失，不另弹提示。操作卡盖住部分地图，所选地块被盖住时地图会平移，自动输入每次应重新读取只读格子屏幕位置。

城市画布填满视口（短边 640 逻辑像素），镜头由 `view/city/geometry.ts` 的 `frameMap` 按地图尺寸推导：总览在格子不小于 44px 时整图放入，否则保持 44px 并可拖动平移（移动超过 8px 算拖动，不触发点选；按住猫不动约 0.35 秒则是提起猫，见上文「长按提起」）；跟随为总览的 1.5 倍。纵向只在常驻的顶部浮条（`#map-heading`）与底部工具条（`#city-tools-nav`）之间取景，每个方向上地图放得下就在该区域居中，放不下就夹紧到铺满该区域，不偏向一侧。“下一步”引导与操作卡浮在地图上，出现、消失或改变高度都不移动地图。唯一例外：所选地块（或所选猫）被操作卡或引导盖住时，地图只移动到刚好露出它，与盖住它的界面留 8px（`geometry.ts` 的 `revealShift`/`revealOffset`）；这次平移跟着选择走，关卡片时地图不回弹，总览里玩家拖出的位置保留，切换总览/跟随时回到居中。在屏幕外的选择（如「出游」点选的远处水域）不算被盖住，地图不动。两组选择器集中在 `view/city/bars.ts`：`bars` 是镜头取景的常驻条，`covers` 是此刻盖住地图的全部界面（常驻条、引导与操作卡）；Harness 点地块用 `bars` 推算镜头，只点地块在 `covers` 之外露出的部分。河畔仍用 640×640 方形画布（体感叠加层与点水瞄准依赖它），画面无边框、最大放到屏宽 1.4 倍并立在抛竿区上方，只裁掉远岸两侧；页面用同色延续天空、远岸与栈桥，因此看起来铺满全屏。

## 内容组织

- 钓具分为配装、补充、线索；包括同行猫、地点、饵、两轴预瞄、旅行与补充鱼饵。钓鱼方式、校准、震动和音效在设置卡里。
- 设置（spec 034；2026-09-30 用户决定：全局一个设置按钮）：每个页面同一个齿轮键（读屏名"设置"，44×44），在顶部浮条下方、贴右边（右边距与浮条同为 8px，并避开 iOS 安全区），与“下一步”那一行垂直居中；小城与河畔是同一个元素，位置相同，小城“下一步”那一行的右端让出齿轮（`--gear-room`）。齿轮（`view/common/settings.ts`）由外壳挂在浮条之后，层级在面板与撸猫画面之上；面板从浮条下开始，齿轮浮在面板右上角，面板标题行右侧让出它的位置（“返回”键左移），撸猫画面见上文「撸猫」。点开同一张设置卡（暖纸底、细线、柔影，靠右浮在浮条下），分两节（标题在 `SETTINGS_COPY`）：「公共设置」对整台设备生效，现在是音效与震动；「本页设置」只和打开它的页面有关，只有河畔有（钓鱼方式、校准甩竿），小城和撸猫画面（盖在河畔上时也是）没有这一节（`common/place.ts` 的 `onPetting` 告诉钓鱼画面撸猫画面开着）。「钓鱼方式」体感 / 按钮分段切换，按下的是正在用的方式；有一竿进行时两段都禁用并写明"这一竿结束后才能换钓鱼方式"；体感被拒时写"体感未获授权 · 点「体感」重试"，点「体感」在这一下里重新请求，再被拒时改写"仍未获授权 · 请在浏览器设置里允许「运动与方向访问」后重试"；不支持时「体感」禁用并写明需 HTTPS 与陀螺仪；想用体感但还没读数时写"等待体感读数…"。「校准甩竿」只在体感瞄准、没有一竿时出现，点下即关闭设置卡、在水面开始校准。震动与音效开关文字写明开或关（如"音效：开"）；音效默认开启，选择按设备记住（`cat-city.sound`），不支持 Web Audio 的浏览器显示"此浏览器不支持音效"并禁用。不能振动的浏览器（如 iPhone Safari）的震动开关写作"画面反馈：开/关"，默认开启；震动不按设备记住：本次打开页面期间在哪个页面看都是同一个值，刷新后回到开。点 ✕、点卡外或按 Esc 关闭，焦点回到齿轮；设置卡是模态对话框，打开时 Tab 只在卡内循环；在面板之上打开时 Esc 先关设置卡，再按一次才关面板。设置卡像面板一样暂停钓鱼输入与收获卡倒计时（钓鱼画面状态的 `settingsOpen` 跟随外壳的设置卡），关闭后需明确继续；换页面时自动关闭。开关由外壳决定，河畔一节显示什么由 `fishingScreen` 的 `settings` 决定（spec 015）。
- 点猫（R-03）：河畔栈桥上陪钓的猫身上盖着一个透明按钮（读屏名"摸摸 Mochi"，可聚焦，回车触发），触摸区域是猫画出来的外接矩形，至少 64×64，只向两侧和下方扩大、不向上伸进体感提示；按 `water-view.ts` 的 `companionBox` 随画布摆放，叠在体感平面之上，一竿进行中点猫不会当成点水提竿。点一下，猫头右侧、与猫头同高冒出一个气泡说一句话（`aria-live="polite"`，尖角指向猫，右边不超出屏幕），1.5 秒后消失；0.5 秒内的重复点击忽略，新的一句替换旧气泡。同时猫做一个小动作：瞄准或两竿之间、咬钩与遛鱼时歪头，等鱼时不动，钓到时小跳（300–500 ms，减少动态效果时不动）。说什么、做什么由纯函数 `fishing/screen.ts` 的 `catReaction` 按这一竿的阶段、收获卡上的这次收获（`shownCatch`）与心情档位决定：瞄准或两竿之间按四档心情说，等咬钩时小声，咬钩与遛鱼时加油，刚钓到时高兴，刚跑了不责备；台词表 `CAT_LINES` 每个时刻两句，按点的次数轮换，每句至多 14 个字。只有话和动作，不改世界，不加心情与亲密。气泡与收获卡（水面上部）、齿轮、体感提示和操作条都不重叠；按钮流程一竿进行时操作条盖住猫的大部分，猫的按钮在操作条之下。
- 鱼篓每页四条，卖鱼/送鱼与补给分开；翻页和页码始终可达。
- 图鉴一页一种鱼，支持选择及前后切换，展示星级、栖息地、长度范围/纪录和品种条件。钓到过的鱼在个人最长旁显示纪录评星：铜、银、金各自有没有（R-54），不显示门槛；三颗都有时插画围一圈金色细线。
- 聊天与回忆分段；对白每页 100 字，长存档回复载入后同样分页，不由其他模块覆盖为全文。

## 钓鱼阶段稳定性

准备、蓄力、等待、咬钩、收线和结算使用相同河面区域与底部操作槽。进度条非活动阶段可隐藏内容但保留位置，按钮不能在指针按住时因阶段重排移动。体感入口不能挡住猫、鱼漂或主要落点。

收线结束时旧按住输入必须释放。随后新出现的准备键只响应从该键开始的新指针操作，旧触摸的抬起/合成 click 不得再开一竿、扣体力或消耗鱼饵；正常键盘激活仍可用。

打开内容（面板、设置卡、撸猫画面）、回城、失焦或切后台会暂停并释放钓鱼输入；回城时还没抛出的一竿（按钮版蓄力阶段）自动收起，不扣资源，猫随即空闲恢复体力，已抛出的一竿暂停等你回来；关闭面板或返回后需明确恢复。暂停的是钓鱼 tick，前台城市时间仍推进营业、步行和体力恢复。场景、分页、暂停、预瞄与镜头均为 View 局部状态，不写 World。

## 降级与可访问性

DOM 控件保留名称、焦点、当前选择和文字状态；不只依赖颜色、动画、震动或图标。方向/近远滑杆提供精确调整，鱼竿支持触摸和 Space/Enter；取消触摸或失焦不遗留按住状态。

支持体感的手机默认使用体感钓鱼（spec 034），没有开启卡片：需要授权的浏览器（iOS）在玩家的点按里自动请求——就是进入河畔的那一下（「河畔」键或地图卡「进入钓点」），否则是之后在河畔的第一次点按（点水面的 `touchend` 也算；设置卡或钓具面板开着、一竿进行中不请求），每次打开页面至多一次；每次被拒都改用按钮流程并提示"体感未获授权，已改用按钮；可在设置里重试"；非 HTTPS 或没有传感器事件时直接用按钮、不提示；无需授权的浏览器收到首个有效读数即启用。桌面（细指针）不自动请求，默认按钮。玩家明确选过的方式按设备记住（`cat-city.fishing-input`）；刷新后恢复的体感一竿（以暂停开始）在暂停时的第一次点按里再请求。允许关闭震动、音效与减弱动画；不能振动的设备在原本振动的时刻改为画面反馈（咬钩、提竿、断线时河面画面轻微震动，鱼线吃紧与上鱼时屏幕边缘暖光一闪），减弱动画时不播放；硬件结果不改 Core。音效（spec 033 F4）用 Web Audio 现场合成、音量轻柔，首次用户手势后才开启音频上下文，页面隐藏时挂起；支持的浏览器设 `navigator.audioSession.type = 'ambient'`，iPhone 静音键可让它静音。真实手机安全区、虚拟键盘、Safari 权限、物理震动、画面反馈强度与实际音色另做实机测试。

### 体感钓鱼（spec 030）

完整设计见 [030 设计](../specs/030-fishing-gestures/design.md)。界面要点：

- 体感进行时隐藏"准备抛竿"、游标条、张力与收线键，底部只留"暂停 / 收竿离开"一行，河面画布尽量放大。
- 瞄准时水面上画落点预测（spec 033 F5，取代原来的竖向力度条；F5b 修订）：从竿尖起一条虚线弧落到落点圈，就是抛出后浮漂要飞的路线（与浮漂共用 `water-view.ts` 的 `flightPoint`），随左右瞄准与俯仰实时移动；体感瞄准时俯仰一项就走满从最近到最远的水面（近远取与力度相同的值，`water-view.ts` 的 `motionAim`），落点到了最近或最远（`castPreview` 的 `limit`）时圈画得更扁、更淡，表示再俯仰也不会更远，读屏的力度值后加"已到最近 / 已到最远"。落点圈与虚线弧在这一竿会落在鱼影上时变深绿，否则是暖光色；判定只问 Core 的 `shadowUnderCast`（与抛竿记下 `shadow` 同一函数），画面不自己推导。鱼影照常显示。体感抛竿按预览所示的方向出竿（滑杆的 5° 一档）。水面上不另标图例文字（用户 2026-09-30 决定删去原右上角的"落点圈变绿＝对准了鱼影"）。力度仍给读屏：视觉隐藏的 `role="meter"` 读"力度 N，精准区间 55–80"。抛出时若 Core 记下了鱼影，提示消息说一次"落在鱼影上"（`screen.ts` 的 `castNotice`，只认同一竿离开蓄力的那次变化，读档不重播；不承诺咬钩）。按钮版蓄力前落点圈同样按对准鱼影变色，蓄力时再画虚线弧（圈随蓄力往返）；水面不画力度区间，蓄力条的绿段照旧。
- 叠加层覆盖河面的开阔水域：瞄准与等待时显示大号提示；假咬口时提示轻晃并轻震；真咬口显示约屏幕短边三成大小的"！"。
- 瞄准提示"左右瞄准 · 俯仰调远近 · 下甩抛竿"每台设备只出现一次（用户 2026-09-30 决定）：没看过时，体感瞄准且引导的逐步提示当前没有显示就显示（引导结束或跳过之后，或引导停在第 4、5 步时重新瞄准），旁边带关闭键（读屏"关闭提示"，触摸区 44×44）；点关闭或它显示时抛出一竿即记为已看过，之后瞄准时水面上没有提示。校准、校准结果与引导的瞄准步骤优先于它，其余阶段的提示不变。"已看过"按设备记在 localStorage（`cat-city.aim-hint`：`seen`），不进世界与存档；判定在 `view-state.ts` 的 `aimHintShown` 与 `aim-hint-seen` 事件。
- 遛鱼时显示随竿尖移动、呼吸收缩的圈（鱼在圈内为鼠尾草绿、圈外为红，中线一圈暖光虚线，鱼线从竿尖连到圈心）、朝游向转身的小鱼影（冲刺前泛起涟漪；随累计进度变大、变深，像被拉近）与累计进度；开头 1.5 秒提示稳住；手指在水面拖动可代替倾斜。
- 鱼连续在圈外（圈为红色）达到按星级的时长就挣脱跑掉（用户 2026-09-30 决定，原来鱼一直在圈外也要等满 15 秒才跑，0★ 鱼的圈"失效"得太久）：0★ 3 秒，每多一星少 0.3 秒，5★ 1.5 秒；回到圈内（绿）重新计时。红圈本身就是提示，不另加计时数字、条或光晕。这样跑掉时结果行写"鱼在圈外太久，挣脱跑了"（`catalog.ts` 的结果文案，按 Core 的 `reason: 'out-of-ring'`）。按钮版不变。
- 首次体感钓鱼逐步引导（spec 033 F3）：提示依次为"左右瞄准"（瞄准偏离正前方至少 15°）→"后仰加力"（力度到 65）→"下甩抛竿"（抛出一竿）→"等"！"再上扬"（在"！"时上扬或点水提竿）→"用圈罩住鱼"（Core 在遛鱼中累计进度），每步做到才出现下一步；前三步在瞄准时教，第 4 步在等待与咬钩时，第 5 步在遛鱼时，别的阶段显示平常提示。校准、校准结果、暂停与"往回拉！"优先于引导。体感平面左上角的"跳过引导"随时结束引导。进度按设备记在 localStorage（`cat-city.fishing-guide`：下一步的名字或 `done`），不进世界与存档；按钮模式没有引导。
- 从未校准过的设备（本地没有调校），第一次能体感瞄准时自动开始校准，提示"校准：手机斜握约 45° 朝脸，稳住后向下快甩两次"，每次打开页面至多一次；之后可在设置里点「校准甩竿」再校准。失败时提示"没认出两次下甩：斜握手机朝脸，甩下去停一下，再到设置点「校准甩竿」"，随后引导继续。校准成功、手稳下来后（`settleMs`），瞄准以那时的姿势为中心（进河畔后换了姿势，例如躺下，也不会偏）；两下甩动回弹得几乎一样快时，只要方向一致并且是这个轴默认的"向下"，也算数（用户 2026-09-30 反馈，真机回弹达 87–93%）。
- 设置卡的「钓鱼方式」在体感与按钮之间切换，选择按设备记住；叠加层与设置只改变 View，不修改 World。遛鱼时顶部的累计进度条两端各留 56px（原为水面上的齿轮让位，齿轮移到浮条下后保留）。

## 视觉基调

## 小城画面

小城地图按风格板「小城格子」用 Phaser 代码绘制（`view/art/city-map.ts`）：大圆角格子配暖棕细描线，已购地为鼠尾草绿、未购地更浅；土路是木栈色格子上的手绘虚线，石板路是暖灰底上的短石板；猫咖杏色、猫公寓樱花粉。颜色集中在 `view/art/city-palette.ts`：`TOKENS` 与 `tokens.css` 的同名变量取值相同（单测核对），地图其余颜色由它们混合得出；标签用正文墨色加暖纸描边，任何时段都可读。格子尺寸、位置、点击区域与镜头算法不因画面改变。

光线随游戏时间变化，由纯函数 `cityLight(minute)`（`view/art/city-light.ts`，有单测）给出：5:00 起清晨柔光，9:00 起白天原色，17:00 起傍晚橘光，20:00 起夜晚转为柔和的暮色（草仍是绿、水仍是蓝，单测核对）。景物颜色按时段向色调混合（至多约两成），地图四周的底色一起变化；选中框、步行路线、标签和猫不染色。傍晚与夜晚窗户亮起暖光，夜晚有几只萤火虫。新游戏从第 1 天 7:00 开始（`CITY_START.minute`），第一眼是清晨。

地图只在内容或时段变化时重绘。草丛轻摇和萤火虫漂移是少量独立小物件，每帧只更新它们的角度与位置（`view/art/city-ambience.ts`），不重画整张地图。开启“减少动态效果”时它们静止（萤火虫留在原处发光）；页面打开期间切换该设置也立即生效。

## 池塘画面

河景（钓点画面）按风格板「池塘：傍晚与鱼影」「光线随时间」改版（美术线 G3）。只改画面：Core、鱼影与命中判定、所有几何（`WATER_VIEW`、竿尖、落点与飞行路线、遛鱼平面）不变。

- 颜色集中在 `view/art/river-palette.ts`。与 UI token 同值的颜色（暖纸、鼠尾草、樱花粉、木栈、深叶、暖棕线、水光、提示红、深绿）照抄 `tokens.css` 的值（`TOKEN`，单测核对两边一致）；其余是美术色：由远到近渐深的薄荷湖水、远岸树与倒影、莲叶、萤火。瞄准的落点圈与虚线弧的颜色（`AIM`：平时暖光，对准鱼影时深绿）也在这里。
- 四个钓点共用天空渐变、平静的水面与缓慢闪光、暖木栈桥。池塘、芦苇河湾与月光湖有远岸树影及水中倒影；池塘有四片莲叶（一片开樱色小花），月光湖两片莲叶，还有自己的月亮与水中月光（白天淡一些）；芦苇河湾两侧的芦苇在手机上也看得到；海岸是海平线与沙滩。鱼影按体型深浅不一，大鱼更深。
- 光线随游戏时间，时段与小城共用 `cityLight(minute)` 的划分：5:00 起清晨柔光，9:00 起白天，17:00 起傍晚橘色，20:00 起夜晚深蓝，有星星与萤火。`riverLook(钓点, minute)` 给出该时该地的全部颜色，栈桥不受光线影响（按钮与卡片就浮在它上面）；画面与页面背景色带（`riverBackdrop`）用同一份，所以总能接上。只有换钓点或时段变化时才重画天空、水面与远岸。
- 动态：水面闪光淡入淡出、莲叶轻轻起伏、夜晚萤火明灭飘动，都是独立的小对象（补间动画），不重画整幅画面。`prefers-reduced-motion: reduce` 时全部静止（闪光与萤火照常显示，只是不动）。
- 鱼竿（spec 033 F6）：提竿时竿尖快速扬起、略过头后停在扬起并弯向浮漂的姿态，遛鱼中弯曲随拉力（`tension`）轻微变化，钓到时再扬一次后放回，脱钩或收竿则直接放回；两种模式相同。姿态由 `view/art/rod-pose.ts` 的纯函数按场景时间算出，`prefers-reduced-motion: reduce` 时直接到最终姿态。原位与之前的画法相同。
- 遛鱼：体感叠加层的圈为鼠尾草绿（鱼在圈外为红），带一圈暖光虚线，外缘随张力由金变红（`--tension`）；顶部的累计进度条与按钮版计量条同样是暖色底、深叶填充的圆角条（尺寸位置不变）。上钩的鱼影更深、边缘柔和，随累计进度（`hold / holdTarget`，CSS 变量 `--near`）放大到 1.3 倍并加深，中心不动：放大后宽 11.7%，最小的圈直径 14% 仍能罩住。按钮版河面上的鱼随进度（`progress`）放大到 2 倍、加深，并朝栈桥游近剩余距离的 35%（`water-view.ts` 的 `hookedFish`）。

## 验收

390×844、360×640 与桌面验证 `scrollHeight <= innerHeight`、页面宽度不溢出、面板与重要控件完整在视口。用真实按钮遍历导航、工具分组、装有多条鱼的鱼篓、全部鱼卡和长对白分页；不能只验空状态。

使用真实地图与钓鱼输入，结合 Debug Bridge 状态、回放、Console 和截图核对到岸、资源消费、暂停及刷新恢复。覆盖阶段尺寸稳定与触摸结算穿透，截图需人工查看；完整规则见[测试与 Harness](testing.md)。

体感回归注入模拟 `devicemotion`/`deviceorientation`（Chromium 与 WebKit）：甩竿只在挥出时创建并抛出一竿且扣一次资源，"！"后上扬进入遛鱼，用圈罩住鱼影累计到钓获；手机（触屏上下文、iOS 式授权替身）点「进入钓点」即在这次手势内请求传感器，没有卡片；刷新后恢复的一竿在第一次点水时再请求；在设置卡切回按钮后叠加层隐藏、按钮流程恢复并按设备记住；新设备自动校准、逐步走完首竿引导，以及跳过引导（其余体感用例预置"已完成引导与校准"）。模拟事件不能代替实机的方向、阈值与手感验证（spec 020）。
