# 界面与输入契约

游戏使用固定单屏：场景铺满整个视口，界面浮在场景上（spec 031），手机与桌面结构相同。主要操作不依赖页面或面板纵向滚动；长内容通过分组/分页显示，不能用裁剪隐藏功能。界面配色见下文「视觉基调」；代码绘图服务辨认角色和反馈，不改变世界状态。

## 场景与导航

| 场景 | 导航与主操作                                                          |
| ---- | --------------------------------------------------------------------- |
| 小城 | 指引 / 猫咪 / 出游；地图铺满，点地、建筑、猫或水域后浮出操作卡        |
| 钓点 | 钓具 / 鱼篓 / 图鉴 / 猫咪；水面铺满，鱼竿键、绿区条及结果卡浮在水面上 |

「猫咪」面板两个场景共用，分页「猫咪」（名册、体力、邀请 Pepper）、「说说话」、「共同回忆」；没有常驻侧栏。

名册卡与「说说话」头部显示心情档位（spec 032）：档位只取 Core 的 `moodBand`，界面配表情和文字（😸 开心 / 😺 平静 / 😾 有点闷 / 😿 低落），读屏读 aria-label 的纯文字；开心时多一行"开心：遛鱼圈更大，经验更多"。结果卡（「这次的收获」）只显示本页、本次来河畔时看着结束的那一竿（`screen.ts` 的 `resultShown`，看的是钓鱼画面状态的 `watched`）；存档里上一次的结果不显示，离开河畔、刷新或出现新的提示消息后也不再显示。心情变化不弹窗：一竿结束或送礼让档位变了，结果卡、钓鱼结果与送礼提示末尾带一句（一竿结束如"Mochi 心情好起来了（平静）"，钓鱼到不了开心；送礼如"Mochi 心情好起来了（开心）"）。当天第 3 条之后的礼物，送礼提示改为"Mochi 今天已经吃饱啦，这条先收下，明天再好好谢你。"（`view/shell/bond.ts` 的 `giftNotice`，spec 038）。文案集中在 `view/shell/mood.ts` 的 `MOOD_COPY`。关系等级（spec 036）同样显示在名册卡（一行爱心与等级名）和「说说话」头部下方（爱心、等级名、到下一级的进度条与"距「信任」还差 8"），由纯函数 `view/shell/bond.ts` 的 `bondBadge` 决定；达到新等级时在促成它的聊天提示、送礼提示或钓鱼结果末尾带一句"和 Mochi 更熟了：信任"（`bondNote`，比较命令前后快照），聊天达到新等级时面板内进度下方也显示这一句（提示条 6 秒后淡出，面板里的这一句留着），读档不重播。

猫咪表情（风格板「猫咪表情」）：地图上的猫、河畔陪伴的猫与名册头像都是圆脸、樱花粉腮红、暖棕描线，表情与耳朵随档位变：开心眯眼笑、耳朵立起；平静圆眼、耳朵立起；有点闷一字眼、耳朵半垂；低落垂眼带泪、耳朵垂下。空闲恢复体力（Core 的 `catIdle` 且体力未满）时蜷成一团打瞌睡，代替原来的 zZ 文字，名册卡另有读屏可读的"在休息"；步行或钓鱼中的猫不蜷起。姿势由纯函数 `view/art/cat-look.ts` 的 `catPose` 决定，Phaser 猫（`view/art/cat.ts` 的 `CatArt.setPose`，换姿势不重建精灵）与 SVG 头像 `catPortrait` 画同一套形状 `CAT_ART`。待机时缓慢呼吸、偶尔眨眼、摇尾巴，只动猫自己的部件，大小与锚点不变；屏幕外的猫和隐藏场景里的猫暂停，减少动态效果时完全静止。「说说话」头部的小头像仍是旧插画。

顶部半透明浮条是场景切换、时钟、速度键与金币（不再显示品牌栏）；底部浮动工具条是当前场景的入口；提示消息在每个页面都在同一处：顶部浮条下方那一行（小城的“下一步”、河畔的钓点名称）的正下方，高度随文字（至多两行），6 秒后淡出，居中、最宽到屏幕两侧各留 16px。小城在浮条下 40px；河畔的钓点名称比“下一步”矮，在浮条下 32px，因此不盖住水面、鱼竿、鱼影、落点圈、设置齿轮、体感的图例与提示，也不盖住钓点名称（390×844、360×640 以及 Safari 带工具栏的 390×664、375×553 都如此）；面板打开时（外壳带 `panel-open`）提示消息改在面板底边、叠在面板之上，不盖住面板的标题、分页与按钮；河畔的设置卡不是面板，照旧盖住提示消息并在卡内写明原因；结果卡与提示消息在同一位置，二者不同时显示：结果卡出现时收起当时还挂着的那条提示消息（`fishing/screen.ts` 的 `noticeShown`）；结果卡显示期间新出现的提示消息照常显示，结果卡让位消失（钓鱼画面状态的 `said` 事件清掉 `watched`），这次的收获仍在钓具面板的结果行与鱼篓里；下一竿开始后照常显示；浮动界面都避开 iOS 安全区。时钟旁唯一的速度键点一次在 1× → 2× → 4× → 1× 间循环，只改变浏览器前台每现实秒推进的游戏分钟数（倍率见 `CITY_TIME.speeds`），按设备记在 localStorage（读取时校验），不进世界与存档；进入河畔等小游戏时回到 1× 并禁用（显示"钓鱼 1×"），回城保持 1×。钓鱼 tick 不受影响。没有其他快进入口；地图卡的"等 10 分钟"只在所选猫步行时出现。

浮条下方常驻一行"下一步"引导，随教程进度变化；完整教程、手动"保存进度"放"指引"页，不显示种子等开发信息。"猫咪"页有名册与"邀请 Pepper"；空闲恢复中的猫蜷成一团打瞌睡（读屏读"在休息"），没有休息按钮。"出游"页列出全部水域及解锁条件，点选后在地图定位该水域并安排真实行走，不能直接传送到可钓场景。切换场景关闭面板，单纯开城市面板或刷新快照不切到钓点。

操作卡不提供 Core 会以可知原因拒绝的操作：按钮禁用，卡片下方一行写明原因（由 `GameSession.check` 按 Core 规则试算，文字来自共享的 `ERROR_MESSAGES`）。选猫后点地块打开该地块卡片，在常规操作旁提供"让 <猫名> 走到这里"；点建筑时只显示建筑操作，公寓卡为每只猫列出"入住"。卡片与名册不使用坐标编号，地图也不画行列标签。

步行（spec 014 §6）：步行按钮写明耗时，如"让 Mochi 走到这里 · 约 18 分钟"，Core 会拒绝时不写；选中猫的卡片写一次"草地 6 分钟/格 · 土路 3 · 石路 2"。地图上步行的猫在整步时间里从一格滑到下一格，所以一直在动，2×、4× 与道路上看得出更快。位置由纯函数 `view/city/walk-glide.ts` 算出：`walkGlide`（一步之内的位置与剩余现实毫秒）、`walkerAt`（沿 Core 排定的路线，不超过体力够走的格数）、`leadMinutes`（两次时钟推进之间按真实时间推算，至多领先一次推进；换速从当前位置继续）与 `catchUp`（世界跳变后约一秒内滑到位，不瞬移）。场景每帧应用，名字与选中框跟着猫，镜头照常跟随。体力耗尽暂停的猫站在格上；受阻或重新寻路后回到 Core 所说的格。减少动态效果时不滑行，逐格移动。

长按提起（spec 035）：选中猫时的提示消息末尾带一句“也可以长按猫咪，拖到想去的地方”（`city/screen.ts` 的 `selectedNotice`）。按住猫约 0.35 秒且手指没有移出 8px，猫被提起——影子升到手指上方跟着走，原地的猫变淡，手指下的地块描绿边（能去）或灰边（不能去）。松手即出发，命令与提示和操作卡的"让 <猫名> 走到这里"/"让 <猫名> 走到岸边"相同；不能去的地块、猫自己的格、地图外、松在浮条或卡片上、触摸被取消都不发生任何事。提起期间地图不平移，拖到屏幕边缘不自动滚动；猫不瞬移，沿路线走过去。手势由纯函数 `view/city/cat-drag.ts` 的 `reduceMapGesture` 判定，能不能去由 `catDrop` 向同一张操作卡的按钮取结果，场景只画。没有震动；减少动态效果时影子不做升起动画。画布关闭了 iOS 长按菜单与文字选择。

到岸后的“进入钓点”先进入预瞄，不创建一竿或消耗资源。玩家可点击水面、调滑杆或启用体感确定两轴落点；只有点击“准备抛竿”才执行 `FISH_BEGIN`、扣除体力/鱼饵并锁定落点。已有一竿时返回钓点恢复同一局，不重复创建或扣费。

面板是覆盖层：手机从浮条下铺到工具条上，桌面为右侧 400px 抽屉；点暗处、返回键或 Esc 关闭。地图默认跟随所选猫，可切总览；点同猫取消选择，选中框消失，不另弹提示。操作卡盖住部分地图，所选地块被盖住时地图会平移，自动输入每次应重新读取只读格子屏幕位置。

城市画布填满视口（短边 640 逻辑像素），镜头由 `view/city/geometry.ts` 的 `frameMap` 按地图尺寸推导：总览在格子不小于 44px 时整图放入，否则保持 44px 并可拖动平移（移动超过 8px 算拖动，不触发点选；按住猫不动约 0.35 秒则是提起猫，见上文「长按提起」）；跟随为总览的 1.5 倍。纵向只在常驻的顶部浮条（`#map-heading`）与底部工具条（`#city-tools-nav`）之间取景，每个方向上地图放得下就在该区域居中，放不下就夹紧到铺满该区域，不偏向一侧。“下一步”引导与操作卡浮在地图上，出现、消失或改变高度都不移动地图。唯一例外：所选地块（或所选猫）被操作卡或引导盖住时，地图只移动到刚好露出它，与盖住它的界面留 8px（`geometry.ts` 的 `revealShift`/`revealOffset`）；这次平移跟着选择走，关卡片时地图不回弹，总览里玩家拖出的位置保留，切换总览/跟随时回到居中。在屏幕外的选择（如「出游」点选的远处水域）不算被盖住，地图不动。两组选择器集中在 `view/city/bars.ts`：`bars` 是镜头取景的常驻条，`covers` 是此刻盖住地图的全部界面（常驻条、引导与操作卡）；Harness 点地块用 `bars` 推算镜头，只点地块在 `covers` 之外露出的部分。河畔仍用 640×640 方形画布（体感叠加层与点水瞄准依赖它），画面无边框、最大放到屏宽 1.4 倍并立在抛竿区上方，只裁掉远岸两侧；页面用同色延续天空、远岸与栈桥，因此看起来铺满全屏。

## 内容组织

- 钓具分为配装、补充、线索；包括同行猫、地点、饵、两轴预瞄、旅行与补充鱼饵。钓鱼方式、校准、震动和音效在河畔设置里。
- 河畔设置（spec 034）：水面左上角一个齿轮键（读屏名"设置"，44×44），点开一张小设置卡（暖纸底、细线、柔影，与钓具面板同一层）。「钓鱼方式」体感 / 按钮分段切换，按下的是正在用的方式；有一竿进行时两段都禁用并写明"这一竿结束后才能换钓鱼方式"；体感被拒时写"体感未获授权 · 点「体感」重试"，点「体感」在这一下里重新请求，再被拒时改写"仍未获授权 · 请在浏览器设置里允许「运动与方向访问」后重试"；不支持时「体感」禁用并写明需 HTTPS 与陀螺仪；想用体感但还没读数时写"等待体感读数…"。「校准甩竿」只在体感瞄准、没有一竿时出现，点下即关闭设置卡、在水面开始校准。震动与音效开关文字写明开或关（如"音效：开"）；音效默认开启，选择按设备记住（`cat-city.sound`），不支持 Web Audio 的浏览器显示"此浏览器不支持音效"并禁用。不能振动的浏览器（如 iPhone Safari）的震动开关写作"画面反馈：开/关"，默认开启，不按设备记住。点 ✕、点卡外或按 Esc 关闭，焦点回到齿轮；设置卡是模态对话框，打开时 Tab 只在卡内循环；齿轮与体感平面按同一算式（`planeBox`）随画布摆放，并叠在平面之上，一竿进行中也点得到；设置卡像面板一样暂停钓鱼输入，离开河畔或打开钓具面板时自动关闭。显示什么由 `fishingScreen` 的 `settings` 决定（spec 015）。
- 鱼篓每页四条，卖鱼/送鱼与补给分开；翻页和页码始终可达。
- 图鉴一页一种鱼，支持选择及前后切换，展示星级、栖息地、长度范围/纪录和品种条件。
- 聊天与回忆分段；对白每页 100 字，长存档回复载入后同样分页，不由其他模块覆盖为全文。
- 保存、旧档显式重置、返回/取消以及输入与发送按钮均在视口可达。

## 钓鱼阶段稳定性

准备、蓄力、等待、咬钩、收线和结算使用相同河面区域与底部操作槽。进度条非活动阶段可隐藏内容但保留位置，按钮不能在指针按住时因阶段重排移动。体感入口不能挡住猫、鱼漂或主要落点。

收线结束时旧按住输入必须释放。随后新出现的准备键只响应从该键开始的新指针操作，旧触摸的抬起/合成 click 不得再开一竿、扣体力或消耗鱼饵；正常键盘激活仍可用。

打开内容、回城、失焦或切后台会暂停并释放钓鱼输入；回城时还没抛出的一竿（按钮版蓄力阶段）自动收起，不扣资源，猫随即空闲恢复体力，已抛出的一竿暂停等你回来；关闭面板或返回后需明确恢复。暂停的是钓鱼 tick，前台城市时间仍推进营业、步行和体力恢复。场景、分页、暂停、预瞄与镜头均为 View 局部状态，不写 World。

## 降级与可访问性

DOM 控件保留名称、焦点、当前选择和文字状态；不只依赖颜色、动画、震动或图标。方向/近远滑杆提供精确调整，鱼竿支持触摸和 Space/Enter；取消触摸或失焦不遗留按住状态。

支持体感的手机默认使用体感钓鱼（spec 034），没有开启卡片：需要授权的浏览器（iOS）在玩家的点按里自动请求——就是进入河畔的那一下（「河畔」键或地图卡「进入钓点」），否则是之后在河畔的第一次点按（点水面的 `touchend` 也算；设置卡或钓具面板开着、一竿进行中不请求），每次打开页面至多一次；每次被拒都改用按钮流程并提示"体感未获授权，已改用按钮；可在设置里重试"；非 HTTPS 或没有传感器事件时直接用按钮、不提示；无需授权的浏览器收到首个有效读数即启用。桌面（细指针）不自动请求，默认按钮。玩家明确选过的方式按设备记住（`cat-city.fishing-input`）；刷新后恢复的体感一竿（以暂停开始）在暂停时的第一次点按里再请求。允许关闭震动、音效与减弱动画；不能振动的设备在原本振动的时刻改为画面反馈（咬钩、提竿、断线时河面画面轻微震动，鱼线吃紧与上鱼时屏幕边缘暖光一闪），减弱动画时不播放；硬件结果不改 Core。音效（spec 033 F4）用 Web Audio 现场合成、音量轻柔，首次用户手势后才开启音频上下文，页面隐藏时挂起；支持的浏览器设 `navigator.audioSession.type = 'ambient'`，iPhone 静音键可让它静音。真实手机安全区、虚拟键盘、Safari 权限、物理震动、画面反馈强度与实际音色另做实机测试。

### 体感钓鱼（spec 030）

完整设计见 [030 设计](../specs/030-fishing-gestures/design.md)。界面要点：

- 体感进行时隐藏"准备抛竿"、游标条、张力与收线键，底部只留"暂停 / 收竿离开"一行，河面画布尽量放大。
- 瞄准时水面上画落点预测（spec 033 F5，取代原来的竖向力度条；F5b 修订）：从竿尖起一条虚线弧落到落点圈，就是抛出后浮漂要飞的路线（与浮漂共用 `water-view.ts` 的 `flightPoint`），随左右瞄准与俯仰实时移动；体感瞄准时俯仰一项就走满从最近到最远的水面（近远取与力度相同的值，`water-view.ts` 的 `motionAim`），落点到了最近或最远（`castPreview` 的 `limit`）时圈画得更扁、更淡，表示再俯仰也不会更远，读屏的力度值后加"已到最近 / 已到最远"。落点圈与虚线弧在这一竿会落在鱼影上时变深绿，否则是暖光色；判定只问 Core 的 `shadowUnderCast`（与抛竿记下 `shadow` 同一函数），画面不自己推导。鱼影照常显示。体感抛竿按预览所示的方向出竿（滑杆的 5° 一档）。叠加层右上角（与左上角的设置齿轮同一行）标"落点圈变绿＝对准了鱼影"。力度仍给读屏：视觉隐藏的 `role="meter"` 读"力度 N，精准区间 55–80"。抛出时若 Core 记下了鱼影，提示消息说一次"落在鱼影上"（`screen.ts` 的 `castNotice`，只认同一竿离开蓄力的那次变化，读档不重播；不承诺咬钩）。按钮版蓄力前落点圈同样按对准鱼影变色，蓄力时再画虚线弧（圈随蓄力往返）；水面不画力度区间，蓄力条的绿段照旧。
- 叠加层覆盖河面的开阔水域：瞄准与等待时显示大号提示；假咬口时提示轻晃并轻震；真咬口显示约屏幕短边三成大小的"！"。
- 遛鱼时显示随竿尖移动、呼吸收缩的圈（鱼在圈内为鼠尾草绿、圈外为红，中线一圈暖光虚线，鱼线从竿尖连到圈心）、朝游向转身的小鱼影（冲刺前泛起涟漪；随累计进度变大、变深，像被拉近）与累计进度；开头 1.5 秒提示稳住；手指在水面拖动可代替倾斜。
- 首次体感钓鱼逐步引导（spec 033 F3）：提示依次为"左右瞄准"（瞄准偏离正前方至少 15°）→"后仰加力"（力度到 65）→"下甩抛竿"（抛出一竿）→"等"！"再上扬"（在"！"时上扬或点水提竿）→"用圈罩住鱼"（Core 在遛鱼中累计进度），每步做到才出现下一步；前三步在瞄准时教，第 4 步在等待与咬钩时，第 5 步在遛鱼时，别的阶段显示平常提示。校准、校准结果、暂停与"往回拉！"优先于引导。设置齿轮下方的"跳过引导"随时结束引导。进度按设备记在 localStorage（`cat-city.fishing-guide`：下一步的名字或 `done`），不进世界与存档；按钮模式没有引导。
- 从未校准过的设备（本地没有调校），第一次能体感瞄准时自动开始校准，提示"校准：向下快甩两次"，每次打开页面至多一次；之后可在设置里点「校准甩竿」再校准。失败时提示"没感到两次一致的下甩，打开设置点「校准甩竿」再试一次"，随后引导继续。
- 设置卡的「钓鱼方式」在体感与按钮之间切换，选择按设备记住；叠加层与设置只改变 View，不修改 World。遛鱼时顶部的累计进度条两端让出齿轮的位置。

## 小城画面

小城地图按风格板「小城格子」用 Phaser 代码绘制（`view/art/city-map.ts`）：大圆角格子配暖棕细描线，已购地为鼠尾草绿、未购地更浅；土路是木栈色格子上的手绘虚线，石板路是暖灰底上的短石板；猫咖杏色、猫公寓樱花粉。颜色集中在 `view/art/city-palette.ts`：`TOKENS` 与 `tokens.css` 的同名变量取值相同（单测核对），地图其余颜色由它们混合得出；标签用正文墨色加暖纸描边，任何时段都可读。格子尺寸、位置、点击区域与镜头算法不因画面改变。

光线随游戏时间变化，由纯函数 `cityLight(minute)`（`view/art/city-light.ts`，有单测）给出：5:00 起清晨柔光，9:00 起白天原色，17:00 起傍晚橘光，20:00 起夜晚转为柔和的暮色（草仍是绿、水仍是蓝，单测核对）。景物颜色按时段向色调混合（至多约两成），地图四周的底色一起变化；选中框、步行路线、标签和猫不染色。傍晚与夜晚窗户亮起暖光，夜晚有几只萤火虫。新游戏从第 1 天 7:00 开始（`CITY_START.minute`），第一眼是清晨。

地图只在内容或时段变化时重绘。草丛轻摇和萤火虫漂移是少量独立小物件，每帧只更新它们的角度与位置（`view/art/city-ambience.ts`），不重画整张地图。开启“减少动态效果”时它们静止（萤火虫留在原处发光）；页面打开期间切换该设置也立即生效。

## 池塘画面

河景（钓点画面）按风格板「池塘：傍晚与鱼影」「光线随时间」改版（美术线 G3）。只改画面：Core、鱼影与命中判定、所有几何（`WATER_VIEW`、竿尖、落点与飞行路线、遛鱼平面）不变。

- 颜色集中在 `view/art/river-palette.ts`。与 UI token 同值的颜色（暖纸、鼠尾草、樱花粉、木栈、深叶、暖棕线、水光、提示红、深绿）照抄 `tokens.css` 的值（`TOKEN`，单测核对两边一致）；其余是美术色：由远到近渐深的薄荷湖水、远岸树与倒影、莲叶、萤火。瞄准的落点圈与虚线弧的颜色（`AIM`：平时暖光，对准鱼影时深绿）也在这里。
- 四个钓点共用天空渐变、平静的水面与缓慢闪光、暖木栈桥。池塘、芦苇河湾与月光湖有远岸树影及水中倒影；池塘有四片莲叶（一片开樱色小花），月光湖两片莲叶，还有自己的月亮与水中月光（白天淡一些）；芦苇河湾两侧的芦苇在手机上也看得到；海岸是海平线与沙滩。鱼影按体型深浅不一，大鱼更深。
- 光线随游戏时间，时段与小城共用 `cityLight(minute)` 的划分：5:00 起清晨柔光，9:00 起白天，17:00 起傍晚橘色，20:00 起夜晚深蓝，有星星与萤火。`riverLook(钓点, minute)` 给出该时该地的全部颜色，栈桥不受光线影响（按钮与卡片就浮在它上面）；画面与页面背景色带（`riverBackdrop`）用同一份，所以总能接上。只有换钓点或时段变化时才重画天空、水面与远岸。
- 动态：水面闪光淡入淡出、莲叶轻轻起伏、夜晚萤火明灭飘动，都是独立的小对象（补间动画），不重画整幅画面。`prefers-reduced-motion: reduce` 时全部静止（闪光与萤火照常显示，只是不动）。
- 鱼竿（spec 033 F6）：提竿时竿尖快速扬起、略过头后停在扬起并弯向浮漂的姿态，遛鱼中弯曲随拉力（`tension`）轻微变化，钓到时再扬一次后放回，脱钩或收竿则直接放回；两种模式相同。姿态由 `view/art/rod-pose.ts` 的纯函数按场景时间算出，`prefers-reduced-motion: reduce` 时直接到最终姿态。原位与之前的画法相同。
- 遛鱼：体感叠加层的圈为鼠尾草绿（鱼在圈外为红），带一圈暖光虚线，外缘随张力由金变红（`--tension`）；顶部的累计进度条与按钮版计量条同样是暖色底、深叶填充的圆角条（尺寸位置不变）。上钩的鱼影更深、边缘柔和，随累计进度（`hold / holdTarget`，CSS 变量 `--near`）放大到 1.3 倍并加深，中心不动：放大后宽 11.7%，最小的圈直径 14% 仍能罩住。按钮版河面上的鱼随进度（`progress`）放大到 2 倍、加深，并朝栈桥游近剩余距离的 35%（`water-view.ts` 的 `hookedFish`）。

## 验收

390×844、360×640 与桌面验证 `scrollHeight <= innerHeight`、页面宽度不溢出、面板与重要控件完整在视口。用真实按钮遍历导航、工具分组、装有多条鱼的鱼篓、全部鱼卡和长对白分页；不能只验空状态。

使用真实地图与钓鱼输入，结合 Debug Bridge 状态、回放、Console 和截图核对到岸、资源消费、暂停及刷新恢复。覆盖阶段尺寸稳定与触摸结算穿透，截图需人工查看；完整规则见[测试与 Harness](testing.md)。

体感回归注入模拟 `devicemotion`/`deviceorientation`（Chromium 与 WebKit）：甩竿只在挥出时创建并抛出一竿且扣一次资源，"！"后上扬进入遛鱼，用圈罩住鱼影累计到钓获；手机（触屏上下文、iOS 式授权替身）点「进入钓点」即在这次手势内请求传感器，没有卡片；刷新后恢复的一竿在第一次点水时再请求；在设置卡切回按钮后叠加层隐藏、按钮流程恢复并按设备记住；新设备自动校准、逐步走完首竿引导，以及跳过引导（其余体感用例预置"已完成引导与校准"）。模拟事件不能代替实机的方向、阈值与手感验证（spec 020）。
