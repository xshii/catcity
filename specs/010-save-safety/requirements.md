# 010 存档安全缺陷

- 状态：完成（批次 1；完整门禁随批次推送）
- 来源：2026-09-28 代码检视（Application、Core）

## 问题

1. 写入失败（如存储已满）时，界面同样显示"清除旧试玩存档"按钮，玩家可能误删有效世界。（`application/session.ts` 的 `storageError` 读写共用）
2. 两个标签页同时打开会互相覆盖存档，没有 `storage` 事件或版本检查。
3. 手工编辑的存档可伪造进行中一竿（如 `phase: fight, progress: 99`、替换鱼种），校验只检查形状，不重新推导。
4. 存档不校验猫的身份与定义一致：改 `breedId` 可解锁不该钓到的鱼，改 `favoriteFish` 改变赠鱼收益，可出现多个 Pepper。

## 验收标准

- 只有读取被拒绝时才出现重置入口；写入失败给出重试提示。
- 多标签页不会静默丢失较新进度（检测到外部更新时停止写入并提示）。
- 进行中一竿的结果与遭遇可从种子和输入重新推导，伪造存档被拒绝。
- 猫的品种、喜好、外观与定义一致，Pepper 至多一只。

## 结果

| 问题                            | 处理                                                                          | 证据                                                 |
| ------------------------------- | ----------------------------------------------------------------------------- | ---------------------------------------------------- |
| 写入失败也显示重置入口          | Session 区分"读档被拒绝"与"写入失败"，重置按钮只看 `saveRejected`             | `tests/integration/save-safety.test.ts`              |
| 多标签互相覆盖                  | 装配入口监听 `storage` 事件；其他标签写入后本页停止保存、提示刷新，不提供重置 | `save-safety.test.ts`、`tests/e2e/save-tabs.spec.ts` |
| 伪造进行中一竿                  | 校验按种子与抛竿输入重新推导鱼种、大小、补给与精准，必须一致                  | `save-safety.test.ts`                                |
| 猫身份与定义不一致、多个 Pepper | 品种、外观、性格、喜好与模板逐项一致；`unique` 模板至多一只；名字保持自由文本 | `save-safety.test.ts`                                |

限制：遛鱼阶段的进度/张力仍只做范围校验；030 重写体感遛鱼时按新模型补足。
