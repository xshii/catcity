# 010 存档安全缺陷

- 状态：提出
- 来源：2026-09-28 代码检视（Application、Core）

## 问题

1. 写入失败（如存储已满）时，界面同样显示"清除旧试玩存档"按钮，玩家可能误删有效世界。（`application/session.ts` 的 `storageError` 读写共用）
2. 两个标签页同时打开会互相覆盖存档，没有 `storage` 事件或版本检查。
3. 手工编辑的存档可伪造进行中一竿（如 `phase: fight, progress: 99`、替换鱼种），校验只检查形状，不重新推导。
4. 存档不校验猫的身份与定义一致：改 `breedId` 可解锁不该钓到的鱼，改 `favoriteFish` 改变赠鱼收益，可出现多个 Pepper。

## 验收标准

- 只有读取被拒绝时才出现重置入口；写入失败给出重试提示。
- 多标签页不会静默丢失较新进度（检测到外部更新时停止写入并提示）。
- 进行中一竿的结果与遭遇可从种子和输入重新推导，伪造存档被拒绝。
- 猫的品种、喜好、外观与定义一致，Pepper 至多一只。
