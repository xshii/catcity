# 035 长按提起猫，拖到地块放开

- 状态：验证中
- 来源：2026-09-29 用户（iPhone 实机）："点击一个猫咪后能否拖动到目标地点然后放开呢？长按一个猫咪提起后到对应位置放开"。此前让猫走过去要三步：点猫、点地块、在卡片上点"让 <猫名> 走到这里"。

## 需求

1. 按住猫约 0.35 秒（`CAT_DRAG.holdMs`）且手指移动不超过 8px（`MAP_VIEW.dragPx`）：猫被提起。不到时间就松手仍是点选；不到时间就移动仍是平移地图。
2. 提起后，猫的影子跟着手指走（画在手指上方，不被手指挡住），原地的猫变淡；手指下的地块描边：能去为绿色，不能去为灰色。提起期间地图不平移；拖到屏幕边缘不自动滚动。
3. 松手：
   - 可步行的地块 → `WALK_CAT`，与操作卡"让 <猫名> 走到这里"是同一条命令，之后同样选中这只猫；
   - 已开放钓点的水格 → `TRAVEL_TO_FISHING_SPOT`，与操作卡"让 <猫名> 走到岸边"是同一条命令，之后选中该水域（到岸后卡片上出现"进入钓点"）；
   - 不能去的地块、猫自己所在的格、地图外、松在浮条或卡片上、触摸被系统取消 → 什么都不发生，猫留在原地。
     猫不瞬移：影子消失，猫按原有方式沿路线走过去。
4. Core 拒绝命令时显示现有的错误提示。点选、操作卡流程、地图平移与镜头规则（spec 031）不变。

5. 玩家在画面上被告知可以这样做：选中猫时的提示消息末尾带一句"也可以长按猫咪，拖到想去的地方"（`view/city/screen.ts` 的 `selectedNotice`，单测与 `city-input.spec.ts` 核对全文）。

## 设计要点

- 不改 Core。能不能去只问操作卡已经在用的判断：`catDrop` 用 `cityScreen` 为"这只猫 + 这块地"算出卡片，取其中未被禁用的"走到这里 / 走到岸边"按钮的命令；没有这个按钮或按钮被禁用就是"不能去"。
- 手势是纯函数 `reduceMapGesture`（`view/city/cat-drag.ts`）：输入带时间与位置的指针事件，输出 空闲 / 按下 / 平移 / 提起 / 点选 / 放下。场景只转发指针事件、画影子与描边，并按结果调用 `City.dropCat`。
- 没有震动：项目里的震动只属于钓鱼的反馈设置，iPhone 网页也不能振动；提起时用影子升起并放大作为提示，减少动态效果时直接到位。

## 验收

- 单测 `tests/unit/cat-drag.test.ts`：手势各阶段；放下的判定与操作卡按钮的命令一致；判定不改世界。
- E2E `tests/e2e/cat-drag.spec.ts`（Chromium，390×844，真实触摸）：长按提起、拖到地块、松手后开始步行且拖动期间地图不动；拖到不能去的水格松手后世界、卡片、提示与命令记录都不变；不停留直接拖动仍平移地图。
- 截图 `artifacts/035-drag-cat/lifted-valid.png`、`lifted-invalid.png` 已人工查看。

## 不做什么

- 拖到屏幕边缘自动滚动地图。
- 拖动建筑、拖到建筑上入住。
- 键盘或读屏的拖放替代：点猫、点地块、操作卡的流程保留，就是无障碍路径。
