- 问题：金币只涨不花。猫咖 300 金币、每游戏小时固定 +10、数量不限、不需要客人，4× 速度下 7.5 分钟回本；建筑与猫无关，猫从不使用猫咖。

## 规则（数值在 `src/content/city.ts`）

> 2026-09-30 spec 041 T-31：居民也是客人（排在伙伴猫之后按编号入座），满城改为 10 伙伴 + 16 居民，经济按四个不变的目标重新定标：结算周期 120 → 180 游戏分钟，猫咖 `125 × 2^(n−1)`，居民楼 `3000 × 1.6^(n−1)`，公寓不变。本文下面的数值与测得的表是 T-31 之前的；现行数值与实测见 [041 design.md 6.6](../041-master-plan/design.md#66-经济重新定标)。

| 项目     | 规则                                                                                                                            |
| -------- | ------------------------------------------------------------------------------------------------------------------------------- |
| 猫咖收入 | 每位客人每 120 游戏分钟 1 金币；全城同时结算：游戏时钟走到 120 的整数倍分钟时，所有猫咖按这一刻的同一次座位分配结算             |
| 客人     | 有住所的猫，住所（公寓）到猫咖的格距 ≤ 3；看的是住所，不是猫此刻站的位置                                                        |
| 归属     | 每只猫只算一家的客人。猫按 ID 顺序入座（Mochi 最先，其余按编号）：去住所 3 格内还有空位的最近一家；同距离时算建筑 ID 较早的一家 |
| 上限     | 每家最多 5 位客人；最近的一家坐满时去范围内下一家有空位的；范围内都没有空位的猫不算任何一家的客人                               |
| 无客人   | 没有客人的猫咖没有收入，也不产生 `IncomeGenerated` 事件                                                                         |
| 猫咖价格 | 第 n 家 `200 × 2^(n−1)`：200、400、800、1600、3200…                                                                             |
| 公寓价格 | 第 n 座 `300 × 1.8^(n−1)`：300、540、970、1750、3150、5670、10205、18365…                                                       |
| 土地价格 | `50 + 25 × d`                                                                                                                   |
| 搬移     | 免费                                                                                                                            |

- **为什么全城同时结算**（2026-09-30 代码评审）：原来每家猫咖按自己的建造时刻结算，而搬移建筑和换住所都免费，玩家可以在甲店结算前把甲店搬到猫的住所旁、在乙店结算前再把乙店搬过去，同一批猫在一个周期里付两次。现在一个周期只有一个结算时刻、一次座位分配，每只猫每个周期最多付一次，中间怎么搬都一样。`builtAtMinute` 仍然入档，但不再决定收入。
- **格距**：沿行列的步数 `|Δx| + |Δy|`（`gridDistance`）。
- **n**：世界里同类建筑的现有数量 + 1，由 `world.buildings` 推导，不入档。当前没有建筑拆除，所以价格只升不降。
- **取整**：取最接近的 5 的倍数；恰好在两个倍数正中间时向下（现在的数列里没有这种情况）。用 BigInt 做精确整数运算（`buildingPrice`），不经过浮点。
- **d**：地块到起始城区矩形（`CITY_START.starterDistrict`，`x,y ∈ 3..6`）的格距减 1，最小为 0。到矩形的格距 = 横向超出的格数 + 纵向超出的格数。与城区共边的地块 d = 0（50 金币）；只与城区对角相接的地块 d = 1（75 金币）；10×10 地图上最远的角 d = 5（175 金币）。
- 客人按"有住所的猫"计算，不区分伙伴猫与将来的居民猫（NPC）；本片不为 NPC 建任何东西。
- 拒绝的命令（金币不足等）不改变世界、不扣费；价格按下命令时的数量计算。

## 存档

没有新增存档字段；本片不改 `SAVE_VERSION`（合并 main 后为 18，来自 038）。价格由建筑数量推导，客人由住所与建筑位置推导。价格与收入规则变了，`CONTENT_VERSION` 9 → 10（main 的步行耗时已占用 9），做法与 014 改路价时相同：save 18 / content 9 的存档作为拒绝 fixture（`tests/fixtures/save-v18-content9.json`，由 main 的代码生成），玩家需要显式重置。

## 界面

- 地块卡的建造按钮显示下一座的真实价格（"猫咖 · 400"）；买地按钮显示这块地的价格（"买下土地 · 75 金币"）。
- 猫咖卡显示客人与每次结算的收入："客人 2/5 · 每 2 小时 2 金币 · Mochi、Pepper"；没有客人时说明"家在 3 格内的猫会来做客，搬移免费"。
- 金币不足时按钮禁用，原因带真实数字："金币不足：需要 400，现有 25。"（仍由 Core 的试算判定，View 只补上数字）。
- 指引页收入行："猫咖 · 客人 1/5 · 每 2 小时 1 金币 · 距离下次结算 60 游戏分钟"。原来的"累计赚取 N 金币"去掉：客人会变，累计值无法由存档推导，而本片不新增存档字段。

## 新手指引

顺序是 **安家 → 入住 → 在家附近开猫咖（有客人） → 共同回忆**，三个步骤标记（猫咪入住、猫咖有客人、共同回忆），阶段由世界此刻的状态推导（`guideProgress`）：

| 阶段     | 条件                     | 提示                                                   | 按钮指向                  |
| -------- | ------------------------ | ------------------------------------------------------ | ------------------------- |
| home     | 没有任何猫有住所         | 建一座猫公寓；已有公寓则"点猫公寓，让 Mochi 入住"      | 推荐空地，或已有的公寓    |
| cafe     | 没有一家猫咖有客人       | 在公寓 3 格内建猫咖；已有猫咖则"把猫咖搬到公寓 3 格内" | 住所 3 格内的空地，或猫咖 |
| remember | Mochi 还没有共同钓鱼记忆 | 点池塘一起钓鱼；说明收入规则与速度键                   | 池塘                      |
| grow     | 以上都完成               | 自由建设                                               | 聊共同回忆                |

- 推荐空地必须是 Core 允许建造的地：已拥有、无路面、无猫无建筑、紧挨一格连到起始路口的道路（用 Core 的 `touchesNetwork`，不是"旁边有任何道路"）。
- **第二步是"猫咖有客人"，不是"猫咖有了收入"**（已知限制）。存档里没有任何事实能说明一家猫咖付过钱，原来由"有客人且开业满一个周期"推导的"已有收入"可以在一枚金币都没付过时完成，也会在搬移后倒退。现在这一步只说此刻为真的事：有客人即完成，猫咖搬远、失去客人时如实变回未完成。
- 因此不再有"等第一笔收入"的阶段，速度键也不再高亮；收入规则和速度键写在下一阶段的说明里，指引页的收入行显示客人、每次结算的金币和距离下次结算的分钟数。
- 要恢复"第一笔收入"这一步，最小的存档事实是世界上的一个整数（猫咖累计付出的金币）；这需要提高存档版本，本片没有做。

### 目标之间的冲突

- A 限定了收入速度：16 位客人 4× 下每现实小时不超过 2,250，即每位客人每游戏小时不超过 0.586 金币。整数金币下可选的是"每 120 分钟 1 金币"或"每 240 分钟 2 金币"（都是 1,920）。
- C 因此限定了第一家猫咖的价格：2 位客人 4× 下一个现实小时最多赚 240，所以起价必须 ≤ 240。原来的 300 无法在 A 成立的同时 60 分钟回本。起价降为 200（50 分钟回本）。
- 结算周期选 120 而不是 240：速度相同，第一笔收入更早（4× 下 30 秒，1× 下 2 分钟），不需要给第一家猫咖另设规则。
- B 要求总价约 4 万，猫咖起价又被 C 压低，所以总价主要由公寓承担，公寓的涨幅从 1.4 提高到 1.8。

## 已知限制

- 指引的第二步是"猫咖有客人"而不是"猫咖有了收入"：存档里没有记录猫咖是否付过钱（见"新手指引"）。
- 范围内的猫咖都坐满时，多出的猫不算任何一家的客人；要靠再建一家猫咖分流。
- 价格最高为金币上限 10 亿（`MAX_PRICE`，与 Core 的 `WORLD_LIMIT` 相同，由单测核对）：第 24 家猫咖、第 27 座公寓起都是 10 亿，实际买不起；建筑数量上限仍是 100。
- 目标 B 的模拟假设 16 只猫已经存在；今天实际只有 Mochi 与 Pepper，收入最多每结算周期 2 金币。

## 已确认

- 2026-09-30 用户确认采用的参数：猫咖每位客人每 120 游戏分钟 1 金币；猫咖 `200 × 2^(n−1)`；公寓 `300 × 1.8^(n−1)`。
- 最后一座公寓很陡（18,365 金币，占住满城市总时间的三分之一以上），暂时接受；如果试玩觉得太陡，退到候选 2（猫咖 `200 × 2.5^(n−1)`、公寓 `300 × 1.75^(n−1)`）。
