## 规则（数值在 `src/content/city.ts`）

| 项目     | 规则                                                                           |
| -------- | ------------------------------------------------------------------------------ |
| 猫咖收入 | 每位客人每完整营业 120 游戏分钟 1 金币；每家沿用自己的建造时刻计时，搬移不重置 |
| 客人     | 有住所的猫，住所（公寓）到猫咖的格距 ≤ 3；看的是住所，不是猫此刻站的位置       |
| 归属     | 每只猫只算一家的客人：离住所最近的一家；同距离时算建筑 ID 较早的一家           |
| 上限     | 每家最多 5 位客人；超出的猫不改去别家，这一家只按 5 位结算                     |
| 无客人   | 没有客人的猫咖没有收入，也不产生 `IncomeGenerated` 事件                        |
| 猫咖价格 | 第 n 家 `200 × 2^(n−1)`：200、400、800、1600、3200…                            |
| 公寓价格 | 第 n 座 `300 × 1.8^(n−1)`：300、540、970、1750、3150、5670、10205、18365…      |
| 土地价格 | `50 + 25 × d`                                                                  |
| 搬移     | 免费                                                                           |

- **格距**：沿行列的步数 `|Δx| + |Δy|`（`gridDistance`）。
- **n**：世界里同类建筑的现有数量 + 1，由 `world.buildings` 推导，不入档。当前没有建筑拆除，所以价格只升不降。
- **取整**：取最接近的 5 的倍数；恰好在两个倍数正中间时向下（现在的数列里没有这种情况）。用 BigInt 做精确整数运算（`buildingPrice`），不经过浮点。
- **d**：地块到起始城区矩形（`CITY_START.starterDistrict`，`x,y ∈ 3..6`）的格距减 1，最小为 0。到矩形的格距 = 横向超出的格数 + 纵向超出的格数。与城区共边的地块 d = 0（50 金币）；只与城区对角相接的地块 d = 1（75 金币）；10×10 地图上最远的角 d = 5（175 金币）。
- 客人按"有住所的猫"计算，不区分伙伴猫与将来的居民猫（NPC）；本片不为 NPC 建任何东西。
- 拒绝的命令（金币不足等）不改变世界、不扣费；价格按下命令时的数量计算。

## 新手指引

顺序改为 **安家 → 入住 → 在家附近开猫咖 → 第一笔收入 → 共同回忆**，仍是三个步骤标记（猫咪入住、猫咖收入、共同回忆），阶段由世界状态推导（`guideProgress`）：

| 阶段     | 条件                             | 提示                                                   | 按钮指向                  |
| -------- | -------------------------------- | ------------------------------------------------------ | ------------------------- |
| home     | 没有任何猫有住所                 | 建一座猫公寓；已有公寓则"点猫公寓，让 Mochi 入住"      | 推荐空地，或已有的公寓    |
| cafe     | 没有一家猫咖有客人               | 在公寓 3 格内建猫咖；已有猫咖则"把猫咖搬到公寓 3 格内" | 住所 3 格内的空地，或猫咖 |
| earn     | 有客人的猫咖营业未满一个结算周期 | 等营业满 2 小时，可调快速度                            | 顶部速度键                |
| remember | Mochi 还没有共同钓鱼记忆         | 点池塘一起钓鱼                                         | 池塘                      |
| grow     | 以上都完成                       | 自由建设                                               | 聊共同回忆                |

推荐空地必须是已拥有、无路面、无猫无建筑、紧挨道路的草地（原来的推荐不检查是否挨着道路）。

### 目标之间的冲突

- A 限定了收入速度：16 位客人 4× 下每现实小时不超过 2,250，即每位客人每游戏小时不超过 0.586 金币。整数金币下可选的是"每 120 分钟 1 金币"或"每 240 分钟 2 金币"（都是 1,920）。
- C 因此限定了第一家猫咖的价格：2 位客人 4× 下一个现实小时最多赚 240，所以起价必须 ≤ 240。原来的 300 无法在 A 成立的同时 60 分钟回本。起价降为 200（50 分钟回本）。
- 结算周期选 120 而不是 240：速度相同，第一笔收入更早（4× 下 30 秒，1× 下 2 分钟），不需要给第一家猫咖另设规则。
- B 要求总价约 4 万，猫咖起价又被 C 压低，所以总价主要由公寓承担，公寓的涨幅从 1.4 提高到 1.8。

## 已知限制

- 指引的"已有收入"是推导值：有客人的猫咖营业满一个结算周期（2 小时）即算完成。若猫咖先空开了一个周期、之后才有猫入住，这一步会在入住时立刻显示完成，而第一笔收入要等到它的下一次结算。
- 一家猫咖被分到超过 5 只猫时，多出的猫不算任何一家的客人；要靠再建一家更近的猫咖分流。
- 第 24 家猫咖、第 27 座公寓起价格超过金币上限（10 亿），实际买不起；建筑数量上限仍是 100。
- 目标 B 的模拟假设 16 只猫已经存在；今天实际只有 Mochi 与 Pepper，收入最多每结算周期 2 金币。
