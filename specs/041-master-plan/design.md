## 1. 不变的原则

下面这些已经在代码里成立，新功能必须继续遵守。它们也是验收时最容易被破坏的地方。

| 原则             | 具体含义                                                                                                 | 在哪里被强制                                                      |
| ---------------- | -------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| Core 是真相      | 世界只通过 `World.dispatch(command)` 改变；View 拿到的快照是冻结的                                       | `src/application/session.ts`、`tests/integration/session.test.ts` |
| 命令先校验       | `commandSchema` 校验形状，规则校验失败抛 `CommandError(code)`；被拒绝的命令不改变世界、不消耗随机数和 ID | `src/core/commands.ts`、`tests/simulation/invariants.test.ts`     |
| 客户端不报结果   | 命令只带输入（抚摸序列、抛竿力度），分数、奖励、遗传结果都由 Core 算                                     | 各命令的单测                                                      |
| 只存事实         | 能从别的字段推导的值不入档（等级、价格、年龄阶段、图鉴评星）                                             | `assertWorld`                                                     |
| 确定性           | 随机来自 `streamSeed(world.seed, 名称, ID)`；不用 `Math.random`、真实时钟                                | `src/core/random.ts`                                              |
| 时间分块等价     | `ADVANCE_TIME 60` 等于 60 次 `ADVANCE_TIME 1`                                                            | `tests/simulation/world.test.ts`                                  |
| 画面由纯模型决定 | 每个画面有 `view-state.ts`（纯 reducer）和 `screen.ts`（纯函数）；DOM 只应用模型                         | spec 015、eslint 规则                                             |
| 数值在 content   | 调参只改 `src/content/**`；测试从 content 读数值，不写死                                                 | —                                                                 |

## 3. 猫的身份模型（R-10、R-11）

### 3.1 问题

现在每只猫必须等于 `CAT_DEFINITIONS` 里的某个模板（`assertTemplate`），邀请命令是写死的 `INVITE_PEPPER`。这让"出生的猫"无法存在。

### 3.2 决定

猫的特征属于实例。模板只用来创建初代猫和校验初代猫。

`CatEntity` 新增字段：

| 字段             | 类型                                 | 说明                                              |
| ---------------- | ------------------------------------ | ------------------------------------------------- |
| `sex`            | `'F' \| 'M'`                         | —                                                 |
| `bornMinute`     | 整数或 `null`                        | 初代猫为 `null`（一直是成年）；出生的猫记出生时刻 |
| `generation`     | 整数 ≥ 1                             | 初代为 1                                          |
| `parents`        | `{ mother: id, father: id } \| null` | 初代为 `null`                                     |
| `neutered`       | 布尔                                 | —                                                 |
| `talent`         | 整数 0–4                             | 见 5.4                                            |
| `lastBredMinute` | 整数或 `null`                        | 冷却用                                            |

`definitionId` 改为可空：初代猫有，出生的猫为 `null`（T-22 实现；T-10 时 Core 还造不出出生的猫，暂保持非空）。

不新增的字段：年龄阶段（由 `bornMinute` 推导）、子女列表（由别的猫的 `parents` 推导）、亲密等级（已是推导）。

### 3.3 校验（保持"存档不能伪造猫"）

`assertWorld` 里：

- `definitionId !== null`：必须 `parents === null`、`generation === 1`、`bornMinute === null`、`talent === 0`，并且品种、花色、性格、喜好、喜欢的鱼、性别都等于模板。
- `definitionId === null`：必须有 `parents`，父母都在 `world.cats` 里（猫永不删除，所以一定在），母亲 `sex === 'F'`、父亲 `sex === 'M'`；然后**用同一个遗传函数重新推导**这只猫的特征并比较，不一致就拒绝。遗传函数的输入只有世界种子、这只猫的 id 和父母，所以可以重算。
- `generation === max(父母) + 1`；`bornMinute ≤ world.minute`；`talent` 在遗传函数允许的范围内。
- 没有环：父母的 id 序号必须小于子女的 id 序号（ID 按分配顺序递增，天然无环）。

### 3.4 被放弃的方案

- **每个出生的猫生成一个新模板**：模板表会进存档，等于把"定义"和"实例"又混在一起。
- **存一份基因串再解码**：没有隐性基因的需求（需求里明确不做），多一层编码没有收益。

## 4. 初代猫与邀请（R-12、R-13）

- `CAT_DEFINITIONS` 扩到 6 只，公母各 3。Mochi（母，布偶）和 Pepper（公，英短）保留。其余 4 只的名字、性格、喜欢的鱼在 content 里定，喜欢的鱼要分散到不同水域，给玩家去不同地方钓鱼的理由。（T-11 实现：年糕、芝麻是布偶，布丁、豆包是英短；Mochi 和 Pepper 占了池塘与芦苇河湾的四种鱼，所以另外四只各喜欢一种潮汐海岸的鱼和一种月光湖的鱼，两两组合各不相同。）
- 命令 `INVITE_PEPPER` 改为 `INVITE_CAT { definitionId }`。不保留旧命令别名（AGENTS.md）。
- 条件：该模板还没被邀请过；伙伴猫数量 < `MAX_COMPANIONS`（10）；有空的公寓床位；金币够。费用 `200 × 2^(已邀请数)`，用和建筑价格相同的整数算法（`content/city.ts` 的 `growingPrice`）。已邀请数只数邀请来的初代猫，不含 Mochi 和调试桥复制的猫。
- 新猫直接入住那张空床（有几张时住进最早建的公寓），出生点是离住所最近的可走格子，平局按 `y`、`x`。
- `MAX_CATS`（引擎上限 16）保留为存档边界；`MAX_COMPANIONS = 10` 放在 `content/cats.ts`，是玩法上限，邀请和生育共用（原为 8，用户 2026-09-30 改为 10，理由见 5.1）。

## 5. 家庭：绝育、生育、世代（R-30 – R-37）

### 5.1 纯函数

```ts
// src/core/family.ts
type BreedBlock =
  | 'SAME_CAT' | 'NEED_PAIR' | 'KITTEN' | 'NEUTERED' | 'NOT_HAPPY'
  | 'BOND_TOO_LOW' | 'RELATED' | 'COOLING_DOWN' | 'NO_BED' | 'COMPANION_LIMIT';

catStage(world, cat): 'kitten' | 'adult'
related(world, a, b): boolean            // 直系（任意代的祖先—后代），或同父 / 同母；叔侄、表亲不算
breedBlocks(world, aId, bId): BreedBlock[] // 空数组表示可以生育；界面逐条显示
// breedBlocks 的三部分，界面按对方、自己、全城分组显示（ui-design 5.4）：
pairBreedBlocks(world, a, b)   // SAME_CAT（同一只时只报这一条）、NEED_PAIR、RELATED
catBreedBlocks(world, cat)     // KITTEN、NEUTERED、NOT_HAPPY、BOND_TOO_LOW、COOLING_DOWN
cityBreedBlocks(world)         // NO_BED（公寓床位 ≤ 有住所的猫）、COMPANION_LIMIT（MAX_COMPANIONS）
inherit(seed, kittenId, mother, father, passed): { breedId, appearance, personality, traits, likes, dislikes, favoriteFish, talent } // core/inheritance.ts; passed = 父母这次传下来的家传数
```

`breedBlocks` 返回**全部**未满足的条件，不是第一条。命令被拒绝时只报其中第一条对应的错误码。

亲属按 R-31 的字面：直系包括父母与子女、祖辈与孙辈，一直往上（用户 2026-09-30 决定）；`related` 沿 `parents` 向上找全部祖先（猫永不删除，父母一定在 `world.cats` 里）。同父或同母的同胞也算；叔侄、表亲不算。后果：小猫也占伙伴猫名额，猫永不删除，五代目至少要 9 只猫——五代目、四代目、三代目、二代目各一只，一对初代父母，再加三只各给一代当另一方父母的猫（每一方都不能是这条线上的祖先或同胞）。上限原为 8 只，只能到四代目（7 只）；用户 2026-09-30 把上限改为 10 只，五代目可以达到，并留一只的余量。

### 5.2 命令

| 命令         | 输入                                  | 规则                                                                                                                                                      |
| ------------ | ------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `NEUTER_CAT` | `catId`                               | 成年、未绝育、金币够；设 `neutered = true`，扣金币                                                                                                        |
| `BREED_CATS` | `motherId`、`fatherId`、`name`、`sex` | `breedBlocks` 为空；分配新 id；性别用玩家起名时选的（用户 2026-09-30），其余 `inherit`；小猫入住空床，出现在离住所最近的可走格子；父母记 `lastBredMinute` |

名字：去掉首尾空白后 1–12 个字符。

### 5.2.1 起名与快捷选名（R-16）

| 项目       | 决定                                                                                                                                                                                                                                                                     |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 名字表     | `src/content/names.ts`：约 60 个中文小名（两到三个字，食物、植物、天气一类），不分性别                                                                                                                                                                                   |
| 推荐       | 纯函数 `suggestNames(world, salt, page) → string[6]`：用 `streamSeed(world.seed, 'names', salt)` 打乱名字表，去掉城里伙伴猫和居民已经用的名字，取第 `page` 组 6 个。生小猫时 `salt` 是下一只猫的 id 序号；改名时是这只猫的 id 序号（Mochi 的 id `mochi` 没有序号，用 0） |
| 换一批     | 只是 `page + 1`，属于画面状态，不发命令、不消耗随机数。名字表用完后回到第一组                                                                                                                                                                                            |
| 为空       | 起名框里留空时，交出的名字是 `suggestNames(world, salt, 0)[0]`，和框里提示的是同一个；命令里的名字不能为空（T-25：命令和存档共用一个名字 schema，空名字不进 Core）                                                                                                       |
| 改名       | 命令 `RENAME_CAT { catId, name }`：只对伙伴猫；不花钱、不限次数、不改任何数值；名字没变时拒绝（`NAME_UNCHANGED`），让回放里没有空操作                                                                                                                                    |
| 校验       | 命令和存档共用 `core/names.ts` 的 `catNameSchema`：1–12 个字符（一个表情算一个），首尾没有空白，不含换行和控制字符。首尾空白由起名框去掉，Core 不改写名字                                                                                                                |
| 重名       | 允许（玩家可能就是想要两只"团子"）。画面在输入框下提醒"城里已经有一只团子了"，不阻止                                                                                                                                                                                     |
| 记忆与对话 | 对话和回忆里的名字都从猫的当前 `name` 读，不把名字写死进已保存的文字；已经保存的聊天记录保持原样                                                                                                                                                                         |

不做：敏感词过滤（单机游戏，名字只有玩家自己看到）；表情符号以外的特殊限制。

### 5.3 随机

遗传用 `runSeed(streamSeed(world.seed, 'inherit'), kittenIdNumber)`（和推荐名同一种写法），先空抽四次，免得相邻种子的前几次抽取挨在一起。抽取顺序固定：品种、外观五项各取父母之一（性别不抽：玩家在起名框里选公或母，用户 2026-09-30）；性格、特点、喜好、讨厌、喜欢的鱼各从父母那里各取一项（两边相同时只留一项）；三项属性各取父母之一；最后打乱三项属性的顺序给家传加成。界面**不预览**遗传结果（预览等于剧透，而且玩家可以反复取消重来）。确认前不分配 id，所以取消不消耗任何东西。

### 5.4 属性与传承

用户 2026-09-30：后代的属性参考《中国式家长》的代际传承——三项属性，加家族传承，再加幼猫期养成。T-22 实现了属性、父母的底子和家传（数值见下）；幼猫期养成是 T-23 的事。

- **三项属性**（`cat.talent`：`feel` 钓感、`stamina` 耐力、`affection` 亲人），各 0–4，初代和邀请来的猫都是 0。每级的效果在 `content/family.ts` 的 `TALENT_EFFECTS`：
  - 钓感：体感版提竿窗口每级 +1 tick（`strikeWindowTicks` 加成，和开心的加成同一路径）；按钮版没有 `strikeWindowTicks`，它的"提竿窗口"是上钩时光标要落进的绿区，每级加宽 2（只在上钩时，不影响遛鱼）。开一竿时把猫的钓感记进这一竿（`feel`），存档校验它等于那只猫的。
  - 耐力：每抛一竿少耗 1 点体力（8 → 最少 4，`castCost`），抛竿和开竿检查都用猫自己的。
  - 亲人：开心的猫（心情 ≥80）每 16 个游戏小时里有 1 / 2 / 3 / 4 个小时（按等级）少回落 1 点（原来每小时 4）；80 以下的回落不变。最初定的"2–3 级每小时 3、4 级每小时 2"让边撸边钓的猫在 4 级时几乎一直开心（99.7%），用户 2026-09-30 要求减弱到约 70% 以下、每级仍有作用，由模拟重新定（见"平衡"）。
- **小猫的属性 = 父母的底子 + 家传**（+ T-23 的幼猫期养成），每项封顶 4：
  - 父母的底子：每一项取父母之一的值，由遗传种子决定（和品种、外观一样"像爸爸或像妈妈"）。不取"较高者减一"：没有幼猫期养成时它会让每一代都掉一级，等于属性衰减。挑谁做另一位家长直接影响下一代。
  - 家传：一只猫和玩家的关系每到一级"亲密""家人"各记一枚家传（`HERITAGE_BOND_LEVELS`；亲密关系只升不降，所以一只猫的家传由存档里的亲密点数推导，不另存）。生小猫时父母当时的家传一共 N 枚传给小猫：种子打乱三项的顺序，前 min(N, 3) 项各 +1，每项一代最多 +1。小猫记下它这一脉的家传数 `heritage` = 父母的家传数 + 这次传下来的 N，一代代累积。所以每项每代最多 +1、初代都是 0，四代之后（五代目）才可能到 4（"五代封顶"，R-35）。
  - 为什么只选这两项成就：它们已经在存档里（亲密点数），而且只增不减、父母成年后也不会消失。"一起钓到金星鱼""一起钓满 100 条"需要每只猫各自的钓获记录，存档里没有（`fishingMemory` 只记第一条，图鉴是全城的），加它们要新增存档字段，交给用户决定。
  - 幼猫期养成（T-23）：幼猫期里多聊天、多撸、带它去河畔看钓鱼，分别让亲人、耐力、钓感的成年值 +1（每项最多一次）。不做就不加，不扣任何东西，也不要求每只都照顾到（遵守"不做维护性杂事"）。
- **存档**：猫身上存三项属性和家传数（`heritage`）。出生的猫（`definitionId` 为 null）读档时用种子、它的 id 序号和"它的家传数 − 父母的家传数"重算 `inherit`，品种、性格、特点、喜好、喜欢的鱼和三项属性必须完全相同（性别不比较：玩家在起名框里选公或母，用户 2026-09-30）；传下来的家传不能多于父母现在的成就（父母之后又升了关系不影响已出生的小猫）。外观不比较：美容院可以改小猫和父母的样子（T-15）。
- **平衡**（`tests/simulation/talent-balance.test.ts`，200 条鱼，断言保留）：新手的 4★ 上鱼率没有属性时平静 1.5%、开心 15%，三项全满时 3%、15.5%——提竿都能提上，但遛鱼决定上不上鱼。边钓边撸的玩家的猫开心的比例按亲人 0–4 级（每 20 / 30 / 45 / 60 游戏分钟一竿）：0 级 56.7 / 55.0 / 50.7 / 60.0%，1 级 61.0 / 61.3 / 53.7 / 63.3%，2 级 62.0 / 62.7 / 54.7 / 64.7%，3 级 65.0 / 65.7 / 56.7 / 67.7%，4 级 67.0 / 67.7 / 58.0 / 69.3%；模拟断言每级都比上一级多、4 级不超过 70%。他的提升最大：2.5 个百分点，低于 10。

## 6. 居民 NPC（R-40 – R-46）

### 6.1 决定：居民是最小的存档事实 + 推导出来的生活

```ts
world.residents: { id: string; home: string; arrivedMinute: number }[]   // 最多 16
```

名字、品种、外观五项、性别由 `residentIdentity(world.seed, id)` 推导，不入档。居民没有位置字段、心情、亲密、记忆。

实现（T-30）：`id` 是 `resident-n`，按到来顺序从 1 编号，不占 `world.nextId`（居民不会离开，到来顺序本身是存档事实，校验要求第 n 只正好是 `resident-n`）。品种、外观与性别取自 `runSeed(streamSeed(seed, 'resident'), n)` 的随机流；名字表先按 `streamSeed(seed, 'resident')` 洗牌，第 n 只取第 n 个名字，所以同一座城的 16 只居民不重名。若改用 `world.nextId` 分配，编号之间的间隔不定，名字只能随机抽，16 只里几乎一定有重名。

### 6.2 到来

`simulate` 在每个游戏日开始的那一分钟（`minute % 1440 === 0`）：如果全城不足 16 只且有居民楼还有空位，编号 `resident-(n+1)`，加入一只居民，住进最老的有空位的居民楼。每天最多一只。玩家没有操作。

### 6.3 位置

```ts
// src/core/residents.ts，纯函数，不读写世界以外的东西
residentPlace(world, resident, minute): { from: Position; to: Position; progress: number }
```

- 每只居民有一个固定的日程周期（例如 240 游戏分钟），相位由它的 id 决定，所以大家不会同时出门。
- 周期内：在家 → 沿路走到它的猫咖 → 在猫咖 → 走回家。路线用现有的 `findWalkingPath` 算一次，按世界快照缓存。
- 没有可达的猫咖时，居民待在家门口。
- 居民**不占格子**：不出现在 `occupied` 校验里，不影响寻路和建设。画面上可以和别的东西重叠，绘制时错开半格并画得比伙伴猫小。

### 6.4 客人

`cafeAssignment` 的输入从"有住所的伙伴猫"改为"有住所的伙伴猫 + 居民"。座位顺序：先伙伴猫（按 id），再居民（按 id）。

### 6.5 被放弃的方案

- **居民也是 `world.cats`**：会继承步行、占格、心情漂移、亲密等全部规则，每多一只居民都在增加模拟成本和校验面，而需求明确说居民首版没有这些。
- **居民完全不入档、只由建筑推导**：那样"每天来一只"无法表达，拆改建筑时居民会凭空变化。

## 7. 心愿（R-50 – R-53）

```ts
cat.wish: { kind: WishKind; target: string | null; sinceDay: number } | null
cat.lastWishDay: number | null      // 上一个心愿完成的那一天，用来保证第二天才有新心愿
```

- 生成：`simulate` 在每个游戏日开始时，对每只没有心愿、`lastWishDay < 今天` 的成年伙伴猫，用 `streamSeed(seed, 'wish', catIdNumber, day)` 决定今天是否想到一个心愿（概率在 content），以及是哪一个。
- 候选只包含**现在做得到**的：想要的鱼必须出自已开放的水域并且这只猫的品种钓得到；"想有个家"只在没有住所时出现；"想家附近有猫咖"只在有住所且 3 格内没有猫咖时出现；"想被摸摸"只在撸猫上线后出现。
- 完成：在对应命令的结算里检查（`GIFT_FISH`、`ASSIGN_HOME`、`BUILD_BUILDING` / `MOVE_BUILDING`、`PET_CAT`、钓到鱼）。完成时清空 `wish`，记 `lastWishDay`，发事件 `WishFulfilled`，给亲密 +10、心情 +10（走 `rewardBond`、`liftMood`）。
- 不会过期受罚。心愿不会因为世界变化而失效；如果它变得已经满足（比如玩家本来就要建猫咖），下一次相关命令结算时自然完成。放着几天没实现，猫会改主意换一个新的：不算失败、没有任何损失、不显示倒计时（用户 2026-09-30）。

实现（T-40）：

- 种类 `FISH`（目标是鱼种）、`HOME`、`CAFE`、`PETTING`、`OUTING`（目标是水域），在 `src/content/wishes.ts`；概率 `WISH.chancePercent`、奖励 `WISH.bond` / `WISH.mood`、改主意的天数 `WISH.changeMindDays` 也在那里。"想要一条某种鱼"首版不带最小体长。
- 随机：`runSeed(streamSeed(seed, 'wish') ^ idNumber(catId), day)`（`idNumber` 是猫 id 的 FNV-1a，撸猫喜好也用它）。先掷有没有心愿，再在现在有目标的种类里等概率选一种，再在它的目标里等概率选一个。
- 候选（`wishTargets`）同时是存档校验：存档里的心愿必须仍是这只猫现在想得到的。水域只会开放、品种不会变；家和家附近的猫咖一满足就在那条命令里实现，所以这条校验对任何能走到的存档都成立。"家附近"就是猫咖的客人范围（`CAFE.range`，3 格）。
- 实现：`GIFT_FISH` 送的是那种鱼（超过当天送鱼的计数也算）；`PET_CAT` 是好的一局（`good`）；钓到一条鱼（不算罐头和金币袋），地点是那处水域；城市命令（买地、铺路、建设、搬移、安排住所）之后检查每只猫的"家"与"家附近的猫咖"，一座猫咖可以同时实现几只猫的心愿。事件 `WishFulfilled` 带种类和目标。
- 奖励走 `rewardBond`（开心的猫多 1 点）和 `liftMood`（开心的猫减半）。钓鱼实现的 `OUTING` 例外：心情走 `liftCalmMood`，只加到开心线下，因为 C3 规定钓鱼不能让猫开心；亲密照常 +10。
- 改主意（用户 2026-09-30）：心愿放了 `changeMindDays`（5）个游戏日还没实现，那天开始时猫换一个新心愿，不掷概率。新心愿用同一个随机流（`wish`、猫、那一天），候选规则不变，只是先排除原来的种类；只剩这一种时才可以还是它（现在的内容里总有别的种类：摸摸、池塘的鱼和池塘一直做得到）。换心愿不动心情、亲密和 `lastWishDay`，不发事件；实现后"当天不再想到新的"照旧。选 5 天的理由：用心的玩家当天就实现心愿（节奏模拟里每个都在想到的那天实现），所以改主意只影响玩家放着不管的心愿；游戏时间只在游玩时走，5 天是 1× 下约 2 小时、4× 下约 30 分钟的游玩：4× 下半小时的一次游玩里，开头想到的心愿到结束都还在，不会读成倒计时；做不到的心愿（比如新手够不着的高星鱼）也不会一直占着。
- 校验还要求：想到的那天不晚于今天、晚于 `lastWishDay`、离今天不满 `changeMindDays` 天（否则猫早该改主意了）、那天猫已经成年（`grownFrom`，幼猫期由出生时刻推导）；`lastWishDay` 不晚于今天。居民没有心愿字段。
- 节奏（`tests/simulation/pacing.test.ts`，一半的日子有心愿、+10、5 天改主意）：一个每个心愿都尽快实现的熟练玩家，1× 时到"家人"677–711 条鱼、心愿占亲密 3.3–7.3%；4× 时 514–647 条、10.7–27.3%。目标只保留 30% 的上限（用户 2026-09-30：心愿是小奖励，不再要求 15% 的下限），1× 与 4× 在 20–60 分钟一竿的各种节奏下都成立。原来的下限在 1× 下达不到：心愿一天至多一个，而 1× 下一个游戏日是约 24 分钟的钓鱼，钓到的鱼给的亲密约是一个心愿的十倍。
- 发现（留给后续任务）：最会钻空子的玩家（送每条算数的喜欢的鱼、摸满每天算数的局数并保持开心、每天聊天、实现每个心愿）到"家人"不到 500 条鱼：没有心愿时 1× 403–473、4× 269–373，加上心愿 1× 375–461、4× 233–347；4× 下只送鱼的玩家 437–564、只撸猫的 388–499 也低于 500。原因是送鱼、撸猫、聊天、心愿都按游戏日计数，4× 下游戏日来得快。用户 2026-09-30 决定另立任务，把这个玩家和 4× 时钟加进节奏模拟并重调亲密数值，不在 T-40 里做；T-40 没有提交这个玩家的测试。

### 10.2 可交互元素不重建（N-6）

教训：操作卡和鱼篓在每次世界变化时 `replaceChildren()`，时钟每秒推进一次，按钮每秒被换掉，点击会丢。

规则：任何在世界变化时运行的 DOM 应用函数，如果它创建可点击的元素，必须满足其一：

1. 模型没变就不动 DOM（把模型序列化成签名比较）；或者
2. 按稳定的 key（实体 id）复用已有元素，只更新文字和 `disabled`。

`src/view/city/actions.ts` 是参考实现。新的名册、鱼篓、家谱都按这个写，并各有一条画面测试：连续 5 次 `ADVANCE_TIME` 后按钮是同一个元素。

## 12. 测试策略

| 层         | 写什么                               | 新功能的最低要求                 |
| ---------- | ------------------------------------ | -------------------------------- |
| 单元       | 每条规则和边界；被拒绝的命令不改世界 | 每个新命令、每个纯函数           |
| 模拟       | 不变量、节奏、经济、平衡             | 每个带数值的功能至少一条区间断言 |
| 集成       | 存档往返、旧档拒绝、回放             | 每次升版                         |
| 画面测试台 | 面板显示、文案、按钮流程、元素不重建 | 每个新画面                       |
| E2E        | 真实触摸、布局、刷新续玩             | 每个新画面一条冒烟，两个手机尺寸 |

模拟测试的写法（来自这一轮的教训）：

- 先写模拟，再定数值。数值设计文档里的估算有三处被模拟推翻。
- 区间是需求，数值是实现。模拟变红时改数值；确实需要改区间时，那是需求变更，要用户同意。
- 不要让结果依赖玩家的操作节奏。任何"按次加、按时间减"的量都会这样，要在多种节奏下断言。
- 每个用例在本机覆盖率下不超过 1 秒。慢的时候先测时间花在哪里，再优化；不要调超时。
- 模拟玩家要包含"最会钻空子的玩家"（钓到喜欢的鱼就送、每局只摸最喜欢的部位），上界由他决定。
