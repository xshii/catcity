# 041 总体规划：美工、界面与操作交互设计

- 配套文档：[需求分析](requirements.md)、[架构设计](design.md)、[任务分解](tasks.md)
- 现有界面契约以 [docs/ui-layout.md](../../docs/ui-layout.md) 为准；颜色、圆角、阴影的值以 `src/view/styles/tokens.css` 为准。本文件只写**新画面和要改的画面**，以及所有画面共同遵守的规则。
- 线框图是结构示意，不是像素稿。宽度按 390 逻辑像素画；360 宽时同一结构，字号不变、间距收紧。
- 本文件里的每一处设计都要在真机上验证后才算定稿。没有一处在 iPhone 上试过。

## 1. 设计原则

| #   | 原则                 | 落到实处是什么意思                                                                                     |
| --- | -------------------- | ------------------------------------------------------------------------------------------------------ |
| P1  | 场景是主角           | 地图和水面铺满屏幕；界面浮在上面，用完就收起。任何常驻元素都不能盖住水面、钓竿、落点圈和正在操作的格子 |
| P2  | 一只手、一块屏       | 主要操作落在屏幕下半部拇指够得到的区域；不靠纵向滚动页面找按钮；长列表只在面板内部滚动                 |
| P3  | 治愈，不催促         | 暖色、圆角、慢动效；没有红点、倒计时压力、连击数字；失败的文案不责备                                   |
| P4  | 猫会回应             | 玩家对猫做的每件事，猫都有看得见的反应（表情、动作、一句话），而不只是数字变化                         |
| P5  | 数字退后             | 先给感受（爱心、表情、一句话），数字放在第二层；需要精确值的地方（价格、进度）才直接给数字             |
| P6  | 说清楚为什么不行     | 按钮不可用时，旁边写原因和怎么解决；不只是变灰                                                         |
| P7  | 不可逆的事要确认     | 花大钱、绝育、生育要确认框；确认框写明后果；默认焦点在"取消"                                           |
| P8  | 每种反馈只有一个位置 | 同类信息总在同一个地方出现，玩家不用找                                                                 |

## 2. 视觉语言

### 2.1 沿用

风格板不变：暖纸底、杏色强调、鼠尾草选中、暖棕描线、圆体字、20px 圆角卡片、柔和暖影。猫是圆脸、樱花粉腮红、2px 暖棕描线。

### 2.2 新增的 token

在 `tokens.css` 里新增，并在 `docs/ui-layout.md` 的表里登记。TS 里用到颜色值的地方（Phaser 绘制）在调色板文件里镜像一份，由单测核对两边一致（沿用 `city-palette.ts` 的做法）。

| Token                       | 值                    | 用途                                   | 对比度要求                                |
| --------------------------- | --------------------- | -------------------------------------- | ----------------------------------------- |
| `--coat-cream`              | `#f7e3c4`             | 奶油花色（已有，登记为 token）         | —                                         |
| `--coat-gray`               | `#c9d0cf`             | 灰（已有）                             | —                                         |
| `--coat-orange`             | `#f2b880`             | 橘                                     | 与描线 `--brown` 3:1 以上                 |
| `--coat-black`              | `#6b5d55`             | 黑白猫的深色块（暖黑，不用纯黑）       | 眼睛和描线改用 `--paper` 才看得清，见 6.1 |
| `--coat-white`              | `#fffaf0`             | 黑白猫的浅色块                         | —                                         |
| `--gen-bg` / `--gen-text`   | `#eee4f3` / `#6d5580` | 世代徽标（淡紫，和心情粉、亲密红区分） | 文字 4.5:1                                |
| `--wish-bg` / `--wish-text` | `#fff1c9` / `#7a5a12` | 心愿（暖黄）                           | 4.5:1                                     |
| `--kitten-scale`            | `0.72`                | 幼猫相对成年猫的大小                   | —                                         |
| `--resident-scale`          | `0.8`                 | 居民相对伙伴猫的大小                   | —                                         |

性别不用颜色区分（避免红蓝刻板和色盲问题），用文字"公 / 母"和符号 ♂ / ♀，读屏读文字。

### 2.3 图标

线性图标，2px 描线，圆头圆角，24×24 视框，颜色 `currentColor`。内联 SVG，不引入图标库。现有的齿轮、房子、爱心、箭头是参照。新增：

| 图标               | 用在哪               | 画法要点                                 |
| ------------------ | -------------------- | ---------------------------------------- |
| 爪印               | 邀请、居民楼         | 一个大圆垫加四个小圆                     |
| 摇篮               | 生育、幼猫           | 半圆篮身加弧形底                         |
| 树                 | 家谱                 | 三个圆点用线连成上二下一                 |
| 星（空 / 半 / 满） | 图鉴评星             | 五角星，铜银金用填充深浅区分，同时有文字 |
| 气泡里的星         | 心愿                 | 对话气泡轮廓内一颗小星                   |
| 沙漏               | 冷却、幼猫期剩余时间 | 两个三角对顶                             |

### 2.4 字号与层级

| 层级 | 字号 / 字重              | 用途                 |
| ---- | ------------------------ | -------------------- |
| 标题 | 20 / 700                 | 面板标题、确认框标题 |
| 名字 | 16 / 700                 | 猫的名字、卡片标题   |
| 正文 | 14 / 400                 | 说明、对白           |
| 辅助 | 12 / 400，`--text-muted` | 次要信息、单位       |
| 徽标 | 12 / 600                 | 心情、世代、心愿徽标 |

最小可点击区域 44×44。同一行里可点击的元素之间至少 8px。

### 2.5 动效

| 类型        | 时长                 | 缓动               | 例子                     |
| ----------- | -------------------- | ------------------ | ------------------------ |
| 出现 / 收起 | 180–220 ms           | ease-out / ease-in | 面板、卡片、气泡         |
| 回应触摸    | 100–140 ms           | ease-out           | 按钮按下、猫被摸到       |
| 猫的动作    | 300–500 ms           | 带一点过冲         | 小跳、歪头、躲开         |
| 环境        | 2–4 s 循环           | sine               | 呼吸、摇尾、水波         |
| 庆祝        | 600–900 ms，只播一次 | ease-out           | 升级、小猫出生、心愿完成 |

规则：一次只有一个庆祝动效；动效不挡操作（庆祝时按钮照常可点）；`prefers-reduced-motion` 下去掉位移和缩放，只保留淡入淡出，环境动效停止。

### 2.6 声音

沿用钓鱼音效模块的合成器和开关。新增的声音都很短、很轻：摸到喜欢的部位（一声短呼噜）、小猫出生（两个上行音）、心愿完成（风铃）。没有背景音乐。声音关闭时玩法不受影响。

## 3. 布局系统

### 3.1 层级（从下到上）

| 层                  | z-index             | 内容                                             | 能否挡住下层的操作 |
| ------------------- | ------------------- | ------------------------------------------------ | ------------------ |
| 场景                | 0                   | Phaser 画布：地图、水面、猫、居民                | —                  |
| 场景内浮层          | 10–20               | 体感水面层、落点圈、点猫的透明按钮、猫头上的气泡 | 只挡自己那一小块   |
| 常驻浮条            | 30                  | 顶栏、场景名、底部工具条                         | 是，但位置固定     |
| 提示条              | 32（面板打开时 38） | 一句话提示                                       | 否（不接收点击）   |
| 浮动卡片            | 33                  | 操作卡、收获卡                                   | 是，只在卡片范围内 |
| 面板遮罩 / 面板     | 35 / 36             | 猫咪、鱼篓、图鉴                                 | 是                 |
| 全屏小游戏          | 40                  | 撸猫                                             | 是                 |
| 设置齿轮            | 41                  | 每个页面同一个，浮条下方、贴右边（2026-09-30）   | 是，只在齿轮范围内 |
| 设置遮罩 / 设置卡   | 42 / 43             | 公共设置、本页设置                               | 是                 |
| 确认框遮罩 / 确认框 | 50 / 51             | 绝育、生育、起名                                 | 是                 |

新元素必须放进这张表里的某一层，不自创 z-index。

### 3.2 屏幕分区

```
┌──────────────────────────────┐
│ 顶栏：地点切换 · 时间 · 速度 · 金币 │  ← 常驻，高 44
├──────────────────────────────┤
│ 场景名 / 下一步提示           ⚙ │  ← 常驻，一行；设置齿轮贴右边
│ 提示条（出现 6 秒后淡出）          │  ← 最多两行
├──────────────────────────────┤
│                              │
│         场  景               │  ← 禁止常驻元素
│    （地图 / 水面）             │
│                              │
├──────────────────────────────┤
│ 浮动卡片（操作卡 / 钓鱼操作键）     │  ← 拇指区
├──────────────────────────────┤
│ 底部工具条                      │  ← 常驻，高 56 + 安全区
└──────────────────────────────┘
```

- 河畔的"场景"区里只允许：落点说明（水面右上）、操作提示（水面下三分之一）、猫和它的气泡（栈桥上）。
- 设置齿轮（2026-09-30 用户决定：全局一个设置按钮）在每个页面的同一位置：浮条下方、贴右边，与场景名 / 下一步那一行垂直居中；那一行的右端和河畔的提示条让出它的位置，面板标题行右侧、撸猫画面的标题行与满足条也让出它。
- 收获卡是例外：它出现在场景区上部，所以有 4 秒自动关闭（R-02）。
- 底部安全区用 `env(safe-area-inset-bottom)`；顶栏用 `env(safe-area-inset-top)`。

### 3.3 尺寸

必须通过的视口：390×844、360×640、375×553（浏览器工具栏展开时的矮屏）、1280×1000（桌面）。矮屏上面板内容可以在面板内部滚动，但面板的标题和关闭按钮始终可见。

## 4. 交互词汇

同一个手势在整个游戏里只有一个含义。

| 手势                 | 含义                         | 在哪里       |
| -------------------- | ---------------------------- | ------------ |
| 点一下               | 选中 / 确认 / 触发           | 到处         |
| 点猫（小城）         | 选中这只猫                   | 地图         |
| 点猫（河畔）         | 猫回应一句                   | 栈桥         |
| 长按猫 0.35 秒后拖动 | 提起猫，拖到哪里松手就去哪里 | 地图         |
| 在地图上拖动         | 平移地图                     | 地图         |
| 在猫身上滑动         | 抚摸                         | 撸猫         |
| 倾斜手机             | 瞄准、调远近、遛鱼           | 河畔体感     |
| 快速下甩 / 上扬      | 抛竿 / 提竿                  | 河畔体感     |
| 点遮罩               | 关闭面板或取消确认框         | 面板、确认框 |
| Esc                  | 关闭最上层                   | 键盘         |

不使用：双击、双指缩放、长按弹菜单（除了提起猫）、从屏幕边缘滑入（和系统手势冲突）。

### 4.1 反馈阶梯

按事情的大小选反馈，不要越级：

| 级别 | 形式                                 | 停留              | 用于                         |
| ---- | ------------------------------------ | ----------------- | ---------------------------- |
| 1    | 元素自身变化（按下、变色、数字跳动） | 即时              | 每次操作                     |
| 2    | 猫头上的气泡                         | 1.5 秒            | 猫的回应                     |
| 3    | 提示条                               | 6 秒              | 命令的结果、被拒绝的原因     |
| 4    | 浮动卡片                             | 到玩家处理或 4 秒 | 钓鱼收获                     |
| 5    | 庆祝卡（居中，带动效）               | 到玩家点"好"      | 亲密升级、小猫出生、心愿完成 |

第 5 级一个游戏日里不应该出现超过几次。同时触发两个时排队，一个关了再出下一个。

### 4.2 确认框

```
┌────────────────────────────┐
│  给 Mochi 做绝育？            │  标题：一句问话
│                            │
│  做了之后 Mochi 不能再生小猫。  │  后果：一到两句
│  这件事不能撤销。              │
│                            │
│  花费 100 金币               │  代价
│                            │
│  ┌──────────┐ ┌──────────┐ │
│  │   取消    │ │  确定绝育  │ │  左取消（默认焦点），右确认
│  └──────────┘ └──────────┘ │
└────────────────────────────┘
```

- 确认按钮的文字写动作本身（"确定绝育""生小猫"），不写"确定 / OK"。
- 不可逆的操作，确认按钮用次按钮样式加 `--text-accent` 文字，不用绿色主按钮，避免顺手点下去。
- 点遮罩、按 Esc 等于取消。焦点限制在确认框内。

### 4.3 不可用的按钮

按钮变灰，并在按钮下方或同一卡片里用 `--text-accent` 写一行原因，格式是"缺什么 + 怎么办"：

- "金币不足：需要 540，现有 500。"
- "没有空床位：先建一座公寓。"
- "Pepper 还在冷却：3 天后可以再生小猫。"

原因文字由纯函数从 Core 的错误码或 `breedBlocks` 生成，不在 DOM 里拼。

- 行是按猫的 id 复用的元素（design.md 10.2）。

### 5.5 撸猫（T-05）

现状的问题（见现有截图）：四个虚线圆按钮直接盖在猫的耳朵、嘴、后背、肚子上，挡住了猫的表情；气泡和"呼噜…"标签重叠。

改成**直接摸猫**：

```

│ 满足 ▓▓▓▓▓░░░░░░░░░░░░░         │
│                                │
│                                │
│          呼噜声起来了 ～          │ ← 节奏提示，固定在猫的上方
│                                │
│        ／￣￣＼＿＿＿＿＿          │
│       ( ᵔ ᴥ ᵔ )        ＼ ～    │ ← 猫：整只都可以摸
│        ＼＿＿／＿＿＿＿＿／        │    被摸到的部位泛起一圈柔光
│                                │
│            喜欢～               │ ← 反应气泡，固定在猫的下方
│                                │
│ ┌──────┬──────┬──────┬──────┐ │
│ │ 头顶  │ 下巴  │ 后背  │ 肚子  │ │ ← 部位条：显示已发现的喜好
│ │  ♥   │  ○   │  ?   │  ✕   │ │    也是键盘和读屏的操作目标
│ └──────┴──────┴──────┴──────┘ │
└────────────────────────────────┘
```

- **猫身上不放任何按钮和文字。** 四个部位是猫身体上看不见的触摸区域（头顶：两耳之间到额头；下巴：嘴以下到胸口；后背：脊背到尾根；肚子：身体下沿）。区域的形状写在 `src/view/art/cat-petting.ts` 里，和画法用同一套坐标。
- 手指落到某个部位：那一块泛起柔光（喜欢的部位是 `--sakura`，一般是 `--apricot`，不喜欢是灰），底部部位条里对应的格子同步高亮。这样玩家在摸的同时知道自己摸的是哪里。
- 节奏提示和反应气泡有固定位置（猫的上方和下方），互不重叠，也不随部位移动。
- 呼噜的节拍用猫身后光晕的明暗表示，同时猫的身体随呼噜轻微起伏。
- 猫躲开：整只猫向后缩并侧过脸，始终留在屏幕内；躲开的 1 秒里触摸区域失效，部位条变淡。
- 部位条的格子可以点（等于在那个部位摸一下），是键盘（方向键选格子，空格抚摸）和读屏的操作方式。
- 没发现的部位显示"?"，发现后显示 ♥ / ○ / ✕。
- 幼猫：猫画得小一号，触摸区域同比例缩小但不小于 44×44。
- 设置齿轮（2026-09-30）浮在这个画面上，位置与其他页面相同（浮条下方、贴右边）；标题行的 ✕ 与满足条的右端让出它。一局进行中打开设置，这一局暂停（倒计时与呼噜节奏都停），关掉后接着走；这里打开的设置卡只有公共设置。

### 5.7 小城：居民与居民楼（T-30 – T-32）

- **居民楼**：和公寓同样大小的一格。外形比公寓高一层、屋顶是鼠尾草绿（公寓是杏色），门口有爪印标志。住了几只就亮几扇窗。

- **猫咖的操作卡**：客人一行区分伙伴和居民，例如"客人 5/5 · Mochi、Pepper 和 3 位居民"。

居民的招呼语按时间段变化（早上 / 白天 / 傍晚 / 夜里各 3 句），由居民的 id 和游戏小时决定用哪句。

### 5.9 图鉴评星（T-42）

用户 2026-09-30 的决定（取代原稿的"再长 3.2 cm 到银星"）：

- 铜、银、金和鱼长绑定：每种鱼的三颗星是它自己的毫米门槛，由它的体长分布和按鱼的星级套用的典型概率推导（`content/fishing/catalog.ts` 的 `STAR_ODDS`）。鱼的星级越高，一条鱼够到金星的概率越低；铜星不是钓到过就有。按个人最长纪录评，不存档。
- 钓到过的鱼，个人最长纪录旁边是铜、银、金三颗星，各自显示有没有收集（★ 有，☆ 没有，后面跟"铜 / 银 / 金"字样；读屏读"体长评星：已收集铜星、银星"）。不显示门槛，也不写还差多少。
- 没钓到的鱼不显示星。
- 三颗都有的鱼，插画周围有一圈金色细线。
- 第一次钓到新鱼种、纪录第一次达到某颗星时，收获卡的附注里说一句（"图鉴新添：鲈鱼，评上铜星"、"银鱼的纪录评上金星"），和心情、亲密变化的附注在同一处，由前后快照比较得出。不用庆祝卡。
- 这一竿钓上来的鱼体长够到这个鱼种的金星（每次都算，不只第一次；`screen.ts` 的 `goldCatch`）：收获卡一闪金光（约 1 秒，不盖住底边的倒计时条），右上角弹出一颗金星并留着；卡片尺寸和位置不变。减少动态效果时不动，只显示那颗金星。只用 CSS 动画。

## 6. 美术规格

### 6.1 猫

所有猫共用一套形状（`CAT_ART`），差异只来自下面几项，这样 10 只伙伴加 16 位居民不需要逐只画。

| 差异 | 取值                     | 画法                                                                                   |
| ---- | ------------------------ | -------------------------------------------------------------------------------------- |
| 花色 | 奶油、灰、橘、黑白       | 纯色猫：填充换色。黑白猫：头顶和后背是深色块，脸下半和胸腹是浅色，分界是一条柔和的曲线 |
| 品种 | 布偶、英短（之后加两种） | 布偶：脸颊两侧有蓬松的毛边，尾巴粗而蓬。英短：脸更圆，耳朵更小更圆，尾巴短             |
| 性别 | 公、母                   | 不改变画法                                                                             |
| 年龄 | 幼猫、成年               | 幼猫：整体 0.72 倍，头身比更大（头不缩那么多，约 0.85 倍），眼睛更大                   |

| 世代 | 1–5                      | 不改变猫的画法；徽标显示                                                               |

深色猫（黑白猫的深色部分）上的眼睛和嘴用 `--paper` 色画，描线保持 `--brown`。

一格一座，正面略俯视，和现有猫咖、公寓同一视角和光源（左上）。用屋顶颜色区分类型，远看就能分辨：

### 6.3 资源形式

全部用代码绘制（Phaser Graphics 和内联 SVG），不引入位图素材。原因：体积小、随 token 换色、和现有画法一致、可以用单测核对颜色。如果以后要换成手绘素材，世界坐标、触摸区域和测试观察接口不变（见 [路线图](../../docs/roadmap.md)）。

## 7. 可及性

| 项目   | 要求                                                                                                                                                 |
| ------ | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| 键盘   | 每个画面都能只用键盘完成：Tab 在可操作元素间移动，方向键在同组元素间移动，回车 / 空格触发，Esc 关闭最上层                                            |
| 焦点   | 3px `--focus-ring` 描边；面板和确认框打开时焦点移进去并限制在内，关闭时回到打开它的按钮                                                              |

## 8. 界面任务的验收

每个带界面的任务，除了 tasks.md 里写的测试，还要交：

1. **截图**：390×844 和 360×640 各一张，保存在 worktree 的 `artifacts/<任务号>/`。执行者要自己看，并在报告里逐张写出看到了什么、有没有重叠或截断。
2. **不重叠检查**：用 `tests/e2e/notice-layer.spec.ts` 的做法（一次 `page.evaluate` 取出所有相关元素的外接矩形），断言新元素不和第 3.2 节禁止区域里的元素相交。
3. **元素不重建检查**：5 次时钟推进后可点击的元素还是同一个（design.md 10.2）。
4. **键盘走一遍**：画面测试台里只用键盘事件完成这个画面的主流程。
5. **文案检查**：所有新文案集中在该画面的 `screen.ts` 或文案表里，没有写死在 DOM 代码里的中文。

真机验收由用户做。执行者在报告的"没验证的部分"里列出需要真机看的点（触摸区域大小、手指遮挡、动效快慢、安全区）。
