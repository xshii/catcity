# 039 撸猫

- 状态：验证中
- 来源：2026-09-29 用户："我还有一个撸猫小游戏没做呢"；硬约束"因为有时候会操作好多只猫，不能把玩家搞的疲于生存"。用户没有指定玩法，本片先实现下面这一种，并在「已知弱点」里写明哪里可能不够好，等试玩后再定。
- 相关：[037 猫咪生活](../037-cat-life/requirements.md) 第 2、7 节与[数值](../037-cat-life/numbers.md)第 5、6 节、[032 心情](../032-mood/requirements.md)、[036 关系等级](../036-bond-levels/requirements.md)、[015 View 状态](../015-view-state/requirements.md)

## 原则

撸猫是玩家自己选的加成，不是维护：不摸不会有任何东西变坏；不花体力和金币，不要求猫在哪里；没有每日任务、提醒或连击排行。

## 规则（数值在 `content/petting.ts`）

| 项目     | 规则                                                                                                                                                                            |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 入口     | 「猫咪」面板名册下方的"摸摸 <猫名>"，对象是所选的猫；这只猫正在一竿钓鱼中时禁用并写明原因（`CAT_BUSY`）                                                                         |
| 一局     | 12 秒（240 tick，每秒 20 tick）；四个部位：头顶、下巴、后背、肚子                                                                                                               |
| 喜好     | 每只猫一个最喜欢、一个不喜欢、两个一般；由世界种子与猫的 id 推导（`pettingTastes`），不入档、永不改变                                                                           |
| 呼噜     | 每 30 tick 一个节拍，前 18 tick 是呼噜声起来的窗口（占六成，宽松）                                                                                                              |
| 一次抚摸 | 最喜欢：窗口内 +10、窗口外 +4；一般：+2 / +1；不喜欢：−8 并躲开 1 秒                                                                                                            |
| 太快     | 1 秒内已有 3 次抚摸时，下一次算太快：−3 并躲开 1 秒（每秒 3 次以内永远不算快）                                                                                                  |
| 躲开     | 躲开的 1 秒内抚摸不算数，也不再扣                                                                                                                                               |
| 满足     | 0–100，局内累计，夹在界内                                                                                                                                                       |
| 心情     | 局末 `2 + ⌊满足 × 6 / 100⌋`，即 +2～+8；不喜欢的部位占这一局抚摸的一半以上时为 −1                                                                                               |
| 心情次数 | 每只猫任意 8 游戏小时内至多 3 局加心情（滑动窗口，`CARE.pettingLifts`），之后的局不加心情；−1 照扣、不占次数。用户 2026-09-30 决定，取代原来的"每游戏小时前 2 局完整、之后减半" |
| 开心     | 加心情走通用的 `liftMood`：猫已经开心（≥80）时再减半（向下取整，至少 1），可以越过开心线（spec 041 R-21）                                                                       |
| 关系     | 满足 ≥ 50 是"表现好"的一局：亲密 +2，猫在这一局开始时开心再 +1；每只猫每游戏日前 3 局计亲密（spec 041 R-20）                                                                    |
| 发现     | 被摸过的部位记为"已发现"，按猫保存；局内当场标记，局末随结算入档                                                                                                                |

## 判定与输入

- 判定全部在纯引擎 `minigames/petting.ts`（整数 tick，不访问世界）。画面为了显示在本地运行同一引擎；一局结束时发出一条 `PET_CAT { catId, strokes: [{ tick, spot }] }`，Core 用同一引擎重放这些抚摸后结算。命令不带分数、心情或满足值，多余字段被拒绝。
- 进行中的一局只存在于 View：中途关闭、按 Esc、切到后台都结束这一局，不发命令，世界不变。一次抚摸都没有的一局也不发命令。
- 触摸：点一个部位是一次抚摸；按住拖动时，手指每在猫身上移动 40px 并落在某个部位上，再算一次（`view/petting/gesture.ts`）。鼠标相同。键盘：方向键在四个部位间移动，空格 / 回车抚摸，Esc 离开，Tab 只在本画面内循环。
- 一局的时钟按真实经过的时间走，不按定时器回调次数：设备繁忙时 12 秒仍是 12 秒；一次最多补 1 秒。
- 减少动态效果时没有过渡动画，呼噜与躲开仍以文字和静态姿势显示。

## 界面

- 全屏暖色画面，直接摸猫（spec 041 ui-design 5.5）：猫侧卧（`view/art/cat-petting.ts`，头部复用 `CAT_ART`），顶部满足条与剩余秒数。猫身上没有按钮和文字：四个部位是猫身体上看不见的触摸区域（`PET_SPOT_REGIONS`，和画法同一套坐标；在 360 宽的手机上每个都不小于 44×44），摸到的部位泛起柔光（最喜欢樱花粉、一般杏色、不喜欢灰）。
- 从上到下：满足条、节奏提示（猫的上方）、猫、反应气泡（猫的下方）、部位条（屏幕底部）。提示和气泡位置固定，互不重叠，不随部位移动。
- 呼噜窗口内猫身后光晕变亮、身体轻微起伏，提示写"呼噜声起来了，现在摸"；窗口外写"慢慢来：等呼噜声起来再摸"。
- 每次抚摸在猫下方冒一句反应（呼噜呼噜♪ / 喜欢～ / 嗯… / 不要摸这里 / 太快啦），约 1 秒；躲开时整只猫向后缩（留在屏幕内）、一字眼、耳朵半垂，部位条变淡。
- 部位条：四格，没发现的显示"?"，已发现的标 ♥ 最喜欢 / ○ 还行 / ✕ 不喜欢，读屏读"下巴，最喜欢"；未发现读"还不知道"。点一格等于在那个部位摸一下；键盘用方向键在格子间移动、空格抚摸。摸猫时对应的格子同步高亮。名册下方写"最喜欢 下巴 · 不喜欢 肚子"。
- 结果页（没有部位条，内容垂直居中）：一句猫自己的话（按性格、摸得最多的部位的喜好、这一局好不好，共 12 句，带部位名）、"心情 +N"和心情档位、"亲密 +N"（计亲密时）、"今天还有 N 次摸摸会让关系更近"或"今天的亲密已经到了，摸摸还是会让它开心"、窗口里的次数用完时写"最近 8 小时里已经摸过 3 回，这一回心情没有再涨"、心情档位或关系等级变化；"再摸一会儿 / 好了"。
- 画面开着时城市时钟固定 1×，速度键显示"撸猫 1×"并禁用（spec 041 R-22）。
- 没有声音：合成器封装在钓鱼音效模块里，复用不止几行，本片不做。

## 存档

- saveVersion 19（18 由成长数值一片使用）。每只猫新增 `petting: { discovered, lifted }`：已发现的部位（按列表顺序、不重复）、最近几局加了心情的局所在的游戏分钟（从早到晚，最多 3 个）；以及 `pettingBond: { day, count } | null`：最近一次计亲密的游戏日与当天已计的局数（与 `giftBond` 相同的每日计数）。
- 喜好、进行中的一局都不入档。v18 存档作为拒绝 fixture（`save-v18-content10.json`）。

## 平衡（`tests/simulation/petting-balance.test.ts`，400 局）

| 模拟玩家                                            | 目标  | 实测 | 表现好的局 |
| --------------------------------------------------- | ----- | ---- | ---------- |
| 随手摸：随机部位，每秒约 2 次，不听呼噜             | +2～3 | 2.87 | 8%         |
| 用心摸：知道最喜欢的部位，听到呼噜（迟 4 tick）再摸 | +6～8 | 6.55 | 100%       |

最初的数值（最喜欢 9/4、一般 4/2、不喜欢 −6）实测为 3.62 与 6.11，随手摸超出目标，因此调整为现在的数值；测试与模拟玩家没有改动。

## 节奏（spec 041 R-23，`tests/simulation/pacing.test.ts`）

用户 2026-09-30 决定：区间不变，把加心情的局数限制改成滑动窗口；目标 1 用最会摸的玩家来量（每个呼噜窗口摸两下最喜欢的部位，一局 +8，design.md 第 12 节"上界由最会钻空子的玩家决定"）。目标 2 的模拟玩家用同一种摸法，以钓鱼为主（熟练手感），每竿之间猫不开心、窗口里还有加心情的局时摸一局。

| 目标                                       | 区间   | 实测（8 小时 3 局）             |
| ------------------------------------------ | ------ | ------------------------------- |
| 从平静（60）到开心（80），一局接一局       | 2–3 局 | 从整点后任何一分钟开始都是 3 局 |
| 钓鱼间隙撸猫，开心的竿占比（每竿 30 分钟） | 70–85% | 75%                             |
| 同上（每竿 60 分钟）                       | 70–85% | 75%                             |

窗口怎么定（最会摸的玩家，每竿 30 / 60 分钟的开心占比）：3 局配 7 小时 78% / 85%，8 小时 75% / 75%，9 小时 66% / 66%；4 局配 10 小时 80% / 80%，11 小时 72% / 73%；2 局时从 60 摸不到 80。用心摸的玩家（晚 4 tick 听到呼噜，一局 +6～7）不作断言，只作参考：8 小时 3 局下开心占比 58%，从 60 连摸 3 局到开心的只有约三分之一，其余要等窗口空出来。

## 不做

- 不做随时间下降的需要、提醒、每日任务、连击排行、体力门槛。
- 不做声音、震动；不做进行中一局的存档与恢复。
- 不改关系与心情的通用规则（由成长数值一片负责）。

## 已知弱点（待试玩确认）

1. 发现太快：四个部位各摸一下就全知道了，"慢慢了解一只猫"只有第一局成立，之后每局都是同一个最优解（只摸最喜欢的部位）。
2. 节奏信号弱：窗口占六成，用心与随手的差别主要来自部位而不是节奏；没有声音时只能看光晕与文字。
3. 两个一般的部位没有存在感（+2 / +1），玩家没有理由去摸。
4. ~~小时上限按游戏时间：4× 速度下一局约 48 游戏分钟，几乎每局都是新的一小时，上限基本不起作用；撸猫时没有像钓鱼那样固定 1×。~~ 已解决：撸猫画面开着时城市时钟固定 1×（spec 041 R-22），一局约 12 游戏分钟；小时上限已改为 8 游戏小时 3 局的滑动窗口（用户 2026-09-30）。
5. 最少一次抚摸就有 +2，窗口里的 3 局都算，可以开局点一下然后等 12 秒；一局没有提前结束的按钮。
6. 局内发现的标记在中途离开时不保存。
7. 猫只有一个姿势。~~部位按钮盖住一部分脸。~~ 已解决：部位是猫身上看不见的触摸区域，按钮在底部的部位条（spec 041 ui-design 5.5）。
