## 2. 设计原则

1. **不疲于生存（用户硬约束）。** 猫多了以后，玩家的必做操作不随猫的数量增长。
   - 没有任何"不照顾就变坏"的逐只维护：不做会随时间上涨、需要逐只喂食的饥饿；不做离线扣减。
   - 猫的基本需要由**城市自动满足**（有住所、附近有设施），这正是建设的意义。
   - 玩家的亲手互动（撸猫、送鱼、一起钓鱼）都是**加成**，不是维持。
   - 同一时间只有玩家正在带着的那只猫需要关注；其余的猫自己生活。
2. **心情是短期状态，亲密是长期积累**，两个都保留（见第 3 节）。
3. **数值不能一下就满**：每个成长量都要给出"到满需要多少实际游玩时间"的目标，并由模拟测试守护。
4. **重大且不可逆的选择要明确确认**：绝育不可撤销；生育会新增一只永久居民。
5. 沿用工程约束：规则在 Core，随机来自种子，拒绝的命令不改变世界，存档版本化。

## 3. 心情与亲密的分工

|          | 心情                   | 亲密                       |
| -------- | ---------------------- | -------------------------- |
| 尺度     | 短期（小时），有涨有落 | 长期，只涨不跌             |
| 含义     | 这只猫现在状态如何     | 你和这只猫走了多远         |
| 玩家手段 | 撸猫、送鱼、一起钓到鱼 | 在猫开心时一起经历事情     |
| 用途     | 当下加成；生育的前提   | 解锁内容；抬高心情的回落点 |

关联规则：

- R3.1 亲密每升一级，该猫心情的回落点 +3（036 已包含）。
- R3.2 猫开心（≥80）时获得的亲密 +2，否则 +1；仍受每游戏小时一次的上限。
- R3.3 亲密永不减少；心情永不因为"玩家没来"而减少。

## 4. 心情的触发

| 方向 | 触发                 | 数值                      | 状态 |
| ---- | -------------------- | ------------------------- | ---- |
| 好   | 钓到鱼               | +3                        | 已有 |
| 好   | 送喜欢的鱼 / 其他鱼  | +8 / +3                   | 已有 |
| 好   | 聊天（每小时一次）   | +2                        | 已有 |
| 好   | 在自己公寓旁         | 每小时 +1                 | 已有 |
| 好   | 撸猫小游戏           | 按表现 +2～+8             | 新   |
| 好   | 住所附近有猫咖等设施 | 回落点 +3（每类设施一次） | 新   |
| 坏   | 鱼跑了               | −3                        | 已有 |
| 坏   | 步行走到体力耗尽     | −5                        | 已有 |
| 坏   | 撸猫摸到不喜欢的部位 | −1                        | 新   |
| 坏   | 没有住所             | 回落点 −5                 | 新   |

说明：坏的触发都来自玩家当下的操作或一次性的城市状态（没有住所），没有一条是"随时间自动变坏"。原方案中的"饿了每小时 −2"因违反原则 1 而删除。

防刷：

- R4.1 心情在 80 以上时，所有加心情的来源减半（向下取整，至少 1）。
- R4.2 撸猫每只猫每游戏小时前 2 次为完整效果，之后减半。

## 5. 心情的应用

| 档位         | 应用                                                       |
| ------------ | ---------------------------------------------------------- |
| 开心 ≥80     | 钓技经验 ×1.5；提竿与鱼圈更宽松（已有）；亲密 +2；可以生育 |
| 平静 50–79   | 一切正常                                                   |
| 有点闷 30–49 | 无加成；猫用表情和一句话表示想被摸或想回家                 |
| 低落 <30     | 无加成；不能生育                                           |

低落没有惩罚性减益：不减经验、不减收益、不禁止钓鱼。坏心情的代价就是"拿不到加成、不能生育"。这与 032 的"只奖励不惩罚"一致。

## 6. 钓技数值

- R6.1 钓技仍是玩家的全局进度（解锁水域用），不改成每只猫各一份：否则换猫就要重练，猫越多越累。
- R6.2 升级曲线改为递增：升到第 n 级累计需要 `20 × n × (n − 1)` 经验（2 级 40，3 级 120，4 级 240，10 级 1800）。
- R6.3 水域解锁等级不变（河湾 2、海岸 3、月光湖 4），所需经验随曲线后移。
- R6.4 开心的猫钓到鱼时经验 ×1.5（向下取整）。
- R6.5 节奏目标（由模拟验证）：月光湖约 12–18 条鱼；满级约 80–120 条鱼。
- R6.6 现有存档的经验不变，等级按新曲线重算（会下降）。若已解锁的水域因此关闭，需用户确认是否接受。

## 7. 撸猫小游戏

玩法待用户确认；下面是需求层面的约束，不含具体操作设计。

- R7.1 短局（10–20 秒），随时可以开始，对猫的位置没有要求，不消耗体力和金币。
- R7.2 每只猫喜欢和不喜欢的部位不同，来自个体数据（由种子在出生或邀请时确定），同一只猫始终一致。
- R7.3 结果只有心情变化和一句反应；亲密经由 R3.2 的每小时上限获得。
- R7.4 触摸与键盘都能完成；判定在 Core，画面只送输入。
- R7.5 不做连击排行、不做体力门槛。

## 8. 绝育

- R8.1 每只成年猫可以绝育一次，不可撤销，操作前明确确认。
- R8.2 绝育的猫不能生育，其余玩法完全不变。
- R8.3 绝育不是惩罚也不是强化：没有数值加成或减益。它的作用是让玩家决定哪些猫参与繁育。
- R8.4 是否收费、是否需要医院建筑：见待确认问题 Q4。

## 9. 生育与世代

条件（全部满足才可以，界面逐条显示哪一条没满足）：

- R9.1 两只猫都是成年、未绝育、心情开心（≥80）。
- R9.2 两只猫与玩家的亲密都达到"信任"。
- R9.3 两只猫不是直系亲属或同胞（父母与子女、同父或同母）。
- R9.4 有一座公寓有空位，小猫直接入住；猫的总数未达上限。
- R9.5 父母各自有冷却（建议 3 个游戏日），期间不能再次生育。
- R9.6 是否区分公母：见待确认问题 Q1。

结果：

- R9.7 由玩家发起、明确确认；一次生一只。
- R9.8 小猫是一只新的独立的猫：自己的 ID、名字（玩家起名，可用默认）、心情、亲密（从 0 开始）、记忆。
- R9.9 世代：最初的居民和邀请来的猫是一代目；小猫的世代 = 父母中较大的世代 + 1。猫面板显示"二代目"等，并能查看父母。
- R9.10 遗传（由种子决定，确认之前不消耗随机数）：
  - 品种：取父母之一。
  - 花色：取父母之一。
  - 喜欢的鱼、喜欢的撸猫部位：父母各取一项。
  - 性格：父母各取一项。
- R9.11 世代天赋：见待确认问题 Q2。
- R9.12 幼猫期：出生后的一段游戏时间（建议 2 个游戏日）是幼猫，可以撸、可以聊天，不能钓鱼、不能生育；之后自动成年。幼猫期不需要任何照顾操作。

与城市的关系：

- R9.13 每只猫需要住所，公寓每座 2 只，因此增加居民要先扩建。这给金币一个长期去处。
- R9.14 猫咖收入与居民挂钩（建议：每家猫咖基础收入不变，服务范围内每有一只居民 +2，上限 +10）。细则另立 spec。

## 10. 伙伴猫与居民猫（NPC）

现状：世界里只有 Mochi 和 Pepper，两只都由玩家调遣，没有 NPC 猫。愿景里"居民、店主、医生和园丁都可以是猫"尚未实现。

|                  | 伙伴猫（认主）          | 居民猫（NPC）                            |
| ---------------- | ----------------------- | ---------------------------------------- |
| 来源             | 初始、邀请、生育        | 城市有空住所和设施后自己搬来             |
| 玩家能否调遣     | 能：步行、钓鱼          | 不能，自己生活                           |
| 心情、亲密、记忆 | 有                      | 首版没有；只有名字、品种、花色、一句招呼 |
| 撸猫、聊天       | 能                      | 首版只能打招呼                           |
| 生育、绝育       | 能                      | 不参与                                   |
| 占用             | 住所 1 位，计入伙伴上限 | 住所 1 位，另计居民上限                  |
| 对城市           | 加成                    | 猫咖的客人、店主：收入来源               |

- R10.1 居民猫按城市状态自动到来和生活，玩家没有任何维护操作（原则 1）。
- R10.2 居民猫在地图上可见：沿道路往返住所与设施，由种子和游戏时间推导，不逐步存档。
- R10.3 猫咖收入与服务范围内的居民数量挂钩（取代 R9.14 中"居民"的含义：伙伴猫与居民猫都算）。
- R10.4 居民猫不挡路：不阻塞伙伴猫的步行与建设。
- R10.5 居民猫变成伙伴猫（"认主"）：见待确认问题 Q7。

## 11. 饥饿

- R11.1 删除 `needs.hunger`（存档版本 +1），或保留字段但不做任何随时间变化的规则。建议删除。
- R11.2 送鱼的效果只保留心情与亲密。

## 12. 不做

- 离线结算、现实时间等待、每日签到。
- 逐只喂食、清洁、看病等维持性操作。
- 猫的衰老、死亡、走失。
- 复杂遗传（隐性基因、突变、稀有度抽取）。
- 出售或放生猫。

## 14. 验收（总则，各切片细化）

- 单测：每条规则与边界；被拒绝的命令不改变世界、不消耗随机数和 ID。
- 模拟：
  - 心情、亲密、钓技的节奏落在第 4–6 节的目标区间内。
  - **负担不随猫数增长**：16 只猫的世界里，玩家 30 个游戏日不做任何照顾操作，没有任何猫的心情低于"平静"下限（50），前提是每只猫都有住所。
  - 随机命令序列下所有数值始终在界内，世代与亲属关系一致（没有猫是自己的祖先）。
- 存档往返与确定性回放一致；旧档拒绝。
- E2E 各一条冒烟：撸猫一局、绝育确认、生育条件提示与一次成功生育。
