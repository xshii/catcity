# 031 全屏布局：场景铺满，界面一致

- 状态：进行中
- 来源：2026-09-29 用户："池塘这种背景能铺满全屏吗，猫咪信息之类的都可以放在聊天里，各个界面都保持一致，可玩的地方最大化"；确认草图：全屏场景 + 顶部半透明浮条 + 底部工具条，猫咪信息进「猫咪·聊天」面板。

## 目标

小城与河畔使用同一结构，手机与桌面一致：

```
┌──────────────────────────┐
│ 小城|河畔   第1天 1×  ●1000│ ← 半透明浮条（场景切换、时钟与倍速、金币）
│                          │
│        场景铺满全屏        │
│                          │
│   提示 / 抛竿键（仅河畔）   │
│ 钓具  鱼篓  图鉴  猫咪      │ ← 底部浮动工具条
└──────────────────────────┘
```

## 需求

1. 场景（小城地图、河畔水面）铺满视口；品牌栏、介绍区、桌面侧栏和页脚不再出现。地图按比例居中，四周用场景底色补满。
2. 顶部浮条：场景切换、时钟与倍速、金币，半透明，不遮挡交互以外的区域；小城的"下一步"引导为浮条下的小标签。
3. 底部浮动工具条：小城「指引 · 猫咪 · 出游」，河畔「钓具 · 鱼篓 · 图鉴 · 猫咪」。提示消息浮在工具条上方。
4. 「猫咪」面板合并原猫咪与聊天：分页「猫咪」（名册、体力、邀请 Pepper）、「说说话」、「共同回忆」。桌面不再有常驻侧栏，与手机一致。
5. 河畔场景里不再放猫咪卡片；钓点名称为左上小标签；准备抛竿键与体感提示浮在水面下方；钓鱼中的暂停/收竿为浮动小按钮。
6. 面板为覆盖层：手机从底部升起，桌面从右侧滑出；打开面板照旧暂停钓鱼输入，关闭回到场景。
7. iOS 安全区（刘海、底部横条）内不放控件；390×844、360×640、桌面 1280×800 下无横向滚动，控件完整可见。

## 验收

- 截图：小城/河畔 × 手机/桌面，场景占满视口，浮条与工具条在安全区内。
- E2E：现有单屏、面板、钓鱼输入回归按新结构更新后全部通过；新增"场景占满视口"断言（画布区域覆盖视口宽度且高度不少于视口 80%）。
- 文档 `docs/ui-layout.md` 与实现一致。

## 进度

- 结构、浮条、工具条、猫咪面板与抽屉已实现；桌面侧栏移除，E2E 改为断言右侧 400px 抽屉（`river-layout.spec.ts` 桌面用例）。
- 城市镜头只在顶部浮条与底部工具条之间取景（`view/city/bars.ts` 的 `bars`），Harness 点地块用同一测量瞄准；`main-page.spec.ts` 地图居中用例按该区域断言。
- 2026-09-29 实机反馈："主页面点击后弹出的图标会导致地图移动"。原因：操作卡与"下一步"引导也算进取景，卡片一出现，镜头就在变小的区域里重新居中。现在二者浮在地图上，不参与取景；只有所选地块被它们盖住时才平移到刚好露出（留 8px），关卡片不回弹。选择器分为镜头取景的 `bars` 与盖住地图的 `covers`，Harness 只点露出的部分。单测见 `map-frame.test.ts`；`main-page.spec.ts` 断言开关卡片时地块屏幕位置不变、底行地块被露出。已知取舍：地图边上的一小条可能被"下一步"引导盖住，点那里的地块会把它露出来。
- 同日用户问："那个已取消猫咪选择的区域是啥？是debug信息吗"。再点已选的猫只取消选择，不再弹"已取消猫咪选择。"；选中时的提示保留。
- 2026-09-29 提示消息的三处修正（只改界面，不改 Core 与存档）：
  - 面板打开时看不到提示消息（如送鱼之后那一句）。原因：`#notice` 的 z-index 32 低于面板 36 与遮罩 35。现在面板打开时外壳带 `panel-open`，提示消息移到面板底边并叠在面板之上（z-index 38），不盖住标题、分页与按钮；河畔设置卡不是面板，照旧盖住提示消息。
  - 结果卡与提示消息重叠（如"落在鱼影上"压在"这次的收获"上）。原因：两者都浮在浮条下方同一位置，提示消息 6 秒才淡出，一竿在此之前结束就叠在一起。现在二者不同时显示，规则在纯模型里：结果卡出现时收起当时还挂着的那条提示消息（`view/fishing/screen.ts` 的 `noticeShown`）；结果卡显示期间新出现的提示消息不会丢（例如下一竿体力不足的原因）：外壳每次显示提示消息都通知钓鱼画面状态（`view-state.ts` 的 `said` 事件），没有一竿进行时它清掉 `watched`，结果卡让位消失，提示消息照常显示；下一竿照旧。取舍：结果卡被提示消息取代后不再回来，这次的收获仍在钓具面板的结果行与鱼篓里。
  - 提示消息用 `left: 50%` 居中，可用宽度只有半屏（034 记录的原有问题）；改为左右各留 16px、按文字宽度居中，390 宽下选猫提示由三行变两行。
  - 证据：`tests/e2e/notice-layer.spec.ts`（390×844 与 360×640：提示消息处最上层元素是它自己，且不与面板和浮条的任何控件相交；结果卡出现时原有提示消息不可见，之后出现的提示消息可见且结果卡消失）、`tests/unit/fishing-screen.test.ts`、`tests/view/fishing-buttons.test.ts`；截图 `artifacts/notice-and-hints/`（`gift-notice-panel-390.png`、`catch-card-390.png`、`cat-selected-390.png` 等，已人工查看）。
- 2026-09-30 实机反馈（iPhone）："提示语可以往下一点不要挡住池塘，和钓竿，或者统一参考主页面的位置最上"。采用后者：提示消息在每个页面都在顶部浮条下方那一行的正下方。
  - 原因：`#notice` 沿用了旧版页面的 `min-height: 55px`（`base.css`），一行字也占 100–155px 这一块；河畔画布顶在浮条下，水面远端（`WATER_VIEW.horizonY`）在 360×640 时在 157px、390×664 时 162px、375×553 时 136px，气泡贴着或压住水面、齿轮、体感图例与判定平面。
  - 处理（只改 `layout.css`）：高度随文字（一行 24px，两行 41px）；河畔在浮条下 32px（钓点名称正下方），小城仍在浮条下 40px（"下一步"正下方）。面板打开时沿面板底边的规则不变，没有冲突；结果卡与提示消息仍不同时显示。
  - 证据：`tests/e2e/notice-layer.spec.ts` 河畔用例（按钮与体感 × 390×844、360×640、390×664、375×553；瞄准、蓄力、等待、咬钩、遛鱼各读一次）：提示消息不与水面（画布自远岸线以下，鱼竿、鱼影、落点圈都画在其中）、齿轮、判定平面、图例、提示、钓点名称、结果卡、浮条相交，且不超过两行。修改前后的截图与各元素的位置在 `artifacts/notice-position/before/`、`after/`（已人工查看）。
  - 已知限制：河畔用例里出现的提示消息都是一行；两行时底边在 133px，按算式仍在 375×553 的水面（136px）之上，未用真实的两行文字在河畔验证。超过两行的文字不会被截断。
