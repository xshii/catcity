# 015 View 状态框架：单一状态、纯画面模型、不变量测试

- 状态：进行中
- 来源：2026-09-29 用户："请你构想一个框架，减少此类 bug 的产生"；"优先加强代码质量，多做逻辑测试，少写点 e2e 测试"

## 问题

同一类 bug 反复出现：河畔操作残留到主页面、手机默认进了按钮模式、关面板后界面不刷新、按钮局里画出体感瞄准。根因是 View 状态散在多个模块的闭包变量里，各自决定显示什么、各自在特定事件后刷新，漏掉一条路径就残留。

## 框架规则

1. **单一 View 状态**：一个场景的可切换状态（地点、面板、暂停/按住、体感偏好与能力、校准、提示）放进一个小 store，只能通过纯 reducer 变化；不变量在 reducer 里强制，并用随机事件序列的单测守护。
2. **纯画面模型**：`screen(世界快照, View 状态)` 决定所有显示、隐藏、文案与禁用；DOM 层只应用它，任何状态或世界变化都触发同一次渲染。
3. **Core 提供预判契约**：View 需要知道规则时调用 Core 的函数（下一 tick 判定的鱼位置、命令为何会被拒），不自行推导规则。
4. **Core 不变量 + 随机命令序列测试**（第 2 步）。
5. **实机日志转回归夹具**（第 3 步）。
6. E2E 只保留真实输入、持久化与接线的少量冒烟；完整套件只在推送前的门禁跑。

## 验收（第 1 步：钓鱼画面）

- `view/fishing/view-state.ts`：钓鱼画面的全部可切换状态与纯 reducer；不变量——不可玩时一定暂停且松开；按住意味着可玩；校准只在体感可用、可玩且没有进行中的一竿时存在。随机 2 万步事件序列单测通过。
- `view/fishing/screen.ts`：纯画面模型，覆盖手动抛竿区、局内控制台、体感画面、开启卡片、快捷切换、设置开关、体感平面、校准键、力度条、提示与暂停文案；单测覆盖每种组合，城市里不显示任何河畔控件。
- `controls.ts`、`motion-fishing.ts`、`panel.ts` 不再各自保存暂停、按住、偏好、能力、校准或提示状态，也不再各自决定可见性；所有入口经 store，一次渲染应用画面模型。
- 修复框架暴露的旧 bug：按钮局进行中若体感已开启，曾在按钮局上叠出体感瞄准界面。
